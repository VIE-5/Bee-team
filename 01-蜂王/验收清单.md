# 验收清单

> 蜂王的质量把关依据。**没过 G3 的东西不许交付。**

## 严格度三档（主人可在任意时刻口头切换）

| 档位 | 适用范围 | 查什么 | 怎么用 |
|---|---|---|---|
| **速查 LIGHT** | 内部草稿、过程稿、给自己看的东西 | 完整性 + 格式（2 项） | 快，容错高 |
| **标准 STANDARD**（**当前默认**） | 日常交付、工蜂正常出货 | 完整性 + 格式 + 合规 + 准确性抽查（4 项） | 性价比最高 |
| **严查 STRICT** | 对外交付、客户提案、公开发布、付费成果 | 六项全查 + 专项条款 | 慢，但对外必过 |

> 切换口令示例：「切严查」「这单用速查」「验收标准档」。
> **判不出来就用标准档**，别自作主张放水。

---

## G1 · 进场验收（派活之前）

**把关对象：派工单本身。** 任务书写不清楚，不许开干。

- [ ] 目标一句话说得清
- [ ] 输入资料齐全且带绝对路径
- [ ] 产出物路径 / 格式 / 命名明确
- [ ] 验收标准可勾选、可判定（无虚词）
- [ ] 边界已划定（不做什么写清楚了）
- [ ] 工蜂角色匹配得上

**不通过** → 退回重写工单，**不许带着含糊开干**。

---

## G2 · 过程抽检（长任务中途）

**只适用于预计耗时长 / 步骤多 / 方向易歪的任务。**

| 触发时机 | 抽检什么 |
|---|---|
| 完成第一个子产物时 | 方向对不对，风格跑没跑偏 |
| 跑完一半里程碑 | 半成品能否达到验收标准的雏形 |
| 换工种接力时 | 上一棒产出是否够下一棒用 |

**发现跑偏** → 当场纠偏，并判定已做部分是否报废。宁可早点毁掉重来，不要拖到最后交一堆废品。

## G3 · 出厂验收（交付之前）

### 六项核心清单

| # | 检查项 | 判定要点 |
|---|---|---|
| 1 | **完整性** | 派工单上要的东西全给了吗？有没有缺件、缺页、缺附录？ |
| 2 | **准确性** | 数据对不对？引用有没有出处？事实能不能复核？数量级有没有离谱？ |
| 3 | **格式** | 文件能打开吗？编码乱不乱？排版有没有崩？命名符合规范吗？ |
| 4 | **合规** | 有没有踩红线：版权 / 商标 / 地图边界 / 肖像 / 个人隐私 / 涉密？引用的开源许可能不能商用？ |
| 4b | **保全项（PRESERVE）** | **返工/修正类任务必查**：是否明确写出「什么不许动」？（2026-10-06 新增，源自 `brand-system-skill` 的 Consistency Audit）<br>修正稿必须显式列出 **PRESERVE 清单**，否则"修 A 坏 B"无从追责。实测教训：修正类的反复返工，多因未锁定成功项。 |
| 4c | **跳过关卡（SKIPPED GATES）** | 本轮**跳过了哪些关卡**？为何跳？**必须写明**。（2026-10-06 新增）<br>把"流程纪律本身"也当作可审计对象 —— 跳过 ≠ 违规，但**隐瞒跳过 = 违规**。 |
| 5 | **可用性** | 拿去就能用吗？要不要二次加工？依赖的东西齐不齐（字体、素材、链接）？ |
| 6 | **一致性** | 术语统一吗？前后口径一致吗？风格跟品牌规范对得上吗？多份材料之间有没有打架？ |

### 工种专项条款（按产出类型叠加，必查）

| 产出类型 | 附加条款 |
|---|---|
| **标识 / Logo / 图标 / 字标类** | ✅ **零水印、零 Logo、零杂字**（硬性）｜✅ **纯平涂、零渐变、零阴影、零渲染**（渲染感 = 不合格）｜✅ **可单色性**（转纯黑仍立得住）｜✅ **缩放到 32px 仍可辨识**｜✅ **深底反白可用**｜✅ 交付含 **SVG 矢量源文件** + 多尺寸 PNG｜✅ 图形是否凝练（能被平铺复用的 = 辅助图案，不是标识） |
| **图片 / 视觉类（生图）** | ✅ **零水印、零 Logo、零文字**（硬性）；分辨率够不够；有无畸形手指/多余肢体；背景是否符合要求 |
| **提案 / PPT 类** | 页数与大纲是否对齐；有无残留占位符（XX、待定、TBD）；字体是否可商用；数据是否标注来源 |
| **多张固定尺寸 deck（HTML 册子/全案封装）** | ⛔ **不许只靠肉眼看截图判完整性** —— 必须跑三条机检：<br>① **截图唯一性**：`md5sum png/*.png \| sort -u \| wc -l` **== 页数**（防 `<uri>#/<N>` 跳页失效导致全截第一屏；**体积"太整齐"就是可疑信号**）<br>② **图片加载**：DOM 探针 `img.naturalWidth === 0` 判失败（图片 404 **不报错、只出碎图**，肉眼极易漏）<br>③ **PDF 页数 == slide 数**（防内容溢出多出一页）<br>⚠️ 另：**标志类素材文件名不可信**（`logo-白.png` 可能是透明底墨稿），**必白底+深底各合成一次目视核对**再判极性；反白稿一律**双色互换**，禁止涂白<br>⛔ **改造型任务（换素材 / 改密度 / 增删页）必须整册重过本条款** —— 改动会外溢（页码、注释、后续页几何全跟着变），**不许按局部验收**；改前留干净备份，**从备份重建**而非在现册上增删页（产线见 skill `deck-rework`） |
| **满幅图 / 原图直出类页面** | ⛔ **「图上叠页眉页脚」不许用遮罩解，优先「几何让位」**：<br>① 先算 `页眉带高（850×15% = 127.5px）` vs `图 contain 后上下空带` —— **空带 < 页眉带就必须让位**<br>② 让位写法：图片容器 `top:var(--hdr); bottom:9%; left/right:var(--mx)` + flex + `object-fit:contain`<br>⚠️ **禁用** `margin:auto + max-width` 那套（绝对定位元素上尺寸解析不可靠，R7 老坑）<br>⚠️ 遮罩（scrim）会把原图染色，客户若要"原图直出"必须彻底删 |
| **字体 / 排版统一性** | ① **字距必须建刻度**（tight/base/wide/en 四档），不许行内硬编码 `.06~.44em` —— 收尾用脚本收编 + 正则复核**旧字面量残留 == 0**<br>② **行高建刻度**（tight/mid/body/cap）<br>③ **数字全局锁** `font-variant-numeric:lining-nums`（写在 `body`，不逐元素补）<br>④ 英文族**单一主选 + 兜底**，不堆气质冲突的字体（避免回退不一致导致粗细忽变） |
| **PDF 导出体积/清晰度** | ⚠️ **`--force-device-scale-factor` 对 `--print-to-pdf` 无效**（scale=1/2 输出字节级同体积）；**文字始终是矢量**（实测字体对象 386~389 个），PDF 体积 100% 由**图片像素总量**决定<br>⛔ **体积与页数无关** —— 实测 45 页 → 60 页（+33%）体积**分毫不差**（均 90.7MB）→ **不许按页数估体积**；**靠合并页面/并置来缩体积是无效手段**<br>→ 体积超限要降的是**素材分辨率**，且分辨率应**按显示尺寸反推**（`所需像素 = 显示宽px × 目标dpi / 96`；221dpi 已够印刷优质档。实测 1920px 塞进 521px 的位子 = 353dpi，属**过剩 2.4 倍**，白烧一倍体积）<br>⚠️ `--force-device-scale-factor=2` **对 `--screenshot` 有效**（可出 2× 高清截图），别与 PDF 混为一谈 |
| **物料 / 多素材入册类** | ✅ **默认「一物料一页」** —— 全案册篇幅不构成交付成本，单体呈现面积才是价值；并置只在主人明确要求时才做<br>⛔ 判据是**单图面积占比**（占内容区 < 10% 细节读不出 / < 20% 偏小 / ≥ 55% 饱满）→ 先跑 `deck-rework/scripts/geo-budget.py` 算，别改完 CSS 才看图小<br>✅ **换素材必须重算几何**（图列宽是硬约束，比例变化直接改变可用高度）<br>✅ 素材内容**逐张开原图核实**（文件名会骗人；实测 29 张里修正 5 处标签误判）<br>✅ 源目录开头 `assert len(os.listdir(SRC)) == len(LABELS)`（防处理期间被追加文件 → 静默漏素材）<br>✅ 结构终检走 `deck-rework/scripts/deck-audit.py`（页数 / 页码序列 / 注释序列 / 图片引用 / 页型 class 计数 / 孤儿素材） |
| **文档 / 报告类** | 结论是否前置；有无抄袭风险段落；链接是否可访问 |
| **资料 / 调研类** | 来源是否可溯源；样本是否有偏；是否区分了「事实」与「推测」 |
| **代码类** | 能否运行；有无硬编码敏感信息；依赖是否声明；有无明显安全隐患 |

### 评分与处置

| 评级 | 含义 | 处置 |
|---|---|---|
| **A** | 六项全过，或仅有无关紧要的瑕疵 | 放行交付 |
| **B** | 有 1-2 项小缺陷，返工成本低 | 打回那只工蜂小修，**注明具体哪里** |
| **C** | 核心项（完整性/准确性/合规）挂了 | 打回重做，并把坑记进 `04-知识沉淀/踩坑库.md` |
