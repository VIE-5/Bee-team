# 验收清单

> 蜂王的质量把关依据。**没过 G3 的东西不许交付。**

## 严格度三档（主人可在任意时刻口头切换）

| 档位 | 适用范围 | 查什么 | 怎么用 |
|---|---|---|---|
| **速查 LIGHT** | 内部草稿、过程稿、给自己看的东西 | 完整性 + 格式（2 项） | 快，容错高 |
| **标准 STANDARD**（**当前默认**） | 日常交付、工蜂正常出货 | 完整性 + 格式 + 合规 + 准确性抽查（4 项） | 性价比最高 |
| **严查 STRICT** | 对外交付、客户提案、公开发布、付费成果 | 六项全查 + 专项条款 | 慢，但对外必过 |

> 切换口令示例：「切严查」「这单用速查」「验收标准档」。
> **判不出来就用标准档**，别自作主张放水。

## G1 · 进场验收（派活之前）

**把关对象：派工单本身。** 任务书写不清楚，不许开干。

- [ ] 目标一句话说得清
- [ ] 输入资料齐全且带绝对路径
- [ ] 产出物路径 / 格式 / 命名明确
- [ ] 验收标准可勾选、可判定（无虚词）
- [ ] 边界已划定（不做什么写清楚了）
- [ ] 工蜂角色匹配得上

**不通过** → 退回重写工单，**不许带着含糊开干**。

---

## G2 · 过程抽检（长任务中途）

**只适用于预计耗时长 / 步骤多 / 方向易歪的任务。**

| 触发时机 | 抽检什么 |
|---|---|
| 完成第一个子产物时 | 方向对不对，风格跑没跑偏 |
| 跑完一半里程碑 | 半成品能否达到验收标准的雏形 |
| 换工种接力时 | 上一棒产出是否够下一棒用 |

**发现跑偏** → 当场纠偏，并判定已做部分是否报废。宁可早点毁掉重来，不要拖到最后交一堆废品。

## G3 · 出厂验收（交付之前）

### 六项核心清单

| # | 检查项 | 判定要点 |
|---|---|---|
| 1 | **完整性** | 派工单上要的东西全给了吗？有没有缺件、缺页、缺附录？ |
| 2 | **准确性** | 数据对不对？引用有没有出处？事实能不能复核？数量级有没有离谱？ |
| 3 | **格式** | 文件能打开吗？编码乱不乱？排版有没有崩？命名符合规范吗？ |
| 4 | **合规** | 有没有踩红线：版权 / 商标 / 地图边界 / 肖像 / 个人隐私 / 涉密？引用的开源许可能不能商用？ |
| 5 | **可用性** | 拿去就能用吗？要不要二次加工？依赖的东西齐不齐（字体、素材、链接）？ |
| 6 | **一致性** | 术语统一吗？前后口径一致吗？风格跟品牌规范对得上吗？多份材料之间有没有打架？ |

### 工种专项条款（按产出类型叠加，必查）

| 产出类型 | 附加条款 |
|---|---|
| **标识 / Logo / 图标 / 字标类** | ✅ **零水印、零 Logo、零杂字**（硬性）｜✅ **纯平涂、零渐变、零阴影、零渲染**（渲染感 = 不合格）｜✅ **可单色性**（转纯黑仍立得住）｜✅ **缩放到 32px 仍可辨识**｜✅ **深底反白可用**｜✅ 交付含 **SVG 矢量源文件** + 多尺寸 PNG｜✅ 图形是否凝练（能被平铺复用的 = 辅助图案，不是标识） |
| **图片 / 视觉类（生图）** | ✅ **零水印、零 Logo、零文字**（硬性）；分辨率够不够；有无畸形手指/多余肢体；背景是否符合要求 |
| **提案 / PPT 类** | 页数与大纲是否对齐；有无残留占位符（XX、待定、TBD）；字体是否可商用；数据是否标注来源 |
| **文档 / 报告类** | 结论是否前置；有无抄袭风险段落；链接是否可访问 |
| **资料 / 调研类** | 来源是否可溯源；样本是否有偏；是否区分了「事实」与「推测」 |
| **代码类** | 能否运行；有无硬编码敏感信息；依赖是否声明；有无明显安全隐患 |

### 评分与处置

| 评级 | 含义 | 处置 |
|---|---|---|
| **A** | 六项全过，或仅有无关紧要的瑕疵 | 放行交付 |
| **B** | 有 1-2 项小缺陷，返工成本低 | 打回那只工蜂小修，**注明具体哪里** |
| **C** | 核心项（完整性/准确性/合规）挂了 | 打回重做，并把坑记进 `04-知识沉淀/踩坑库.md` |
