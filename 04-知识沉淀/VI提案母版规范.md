# VI 全案提案母版规范 v1.0

> 来源：5 本真实交付册 · 231 页 · 创梦餐饮品牌策划设计出品
> （三餐里 35 页 / 小耕班 51 页 / 摘山语 37 页 / 蘑菇围炉 49 页 / 鸽子官 59 页）
> 方法：PPTX 解包 → 原图提取 → 视觉精读 → 像素级版面度量

---

## 0. 先说三个反常识的结论

**① 这 5 本册子用的其实是同一套母版。**
五本画布尺寸、页眉线位置、章节页徽章结构、尾页版式全部高度一致。像素度量给出的页眉分隔线位置：三餐里 12.9%、小耕班 12.5%、摘山语 12.9%、鸽子官 12.3%——**跨册落在 12.3%–13.1% 的 0.8% 窄带内**。这不是巧合，是同一套设计体系的指纹。

**② 交付形态是"一页一图"的图册型 PPT，不是可编辑排版。**
每个 PPTX 里每页只有一张满幅设计稿（`x0% y0% w100% h100%`），PPT 自带的母版、版式全是 Office 默认值，**没有任何真实排版参数**。也就是说：**客户最终拿到的是"设计好的页"，不是"能改的模板"**。想改内容 = 重做那一页。

**③ 全套提案没有页码，模板 A 连页脚都没有。**
唯一的"定位系统"是页眉。这不是省略——是刻意的：**图册型提案靠视觉节奏自证位置，页码会破坏画面净度**。

## 1. 画布规格

| 项 | 值 |
|---|---|
| 比例 | **16:10**（858.9 × 540 pt，即 1.5905） |
| 设计稿分辨率 | 2066×1299 / 2338×1496 / 2755×1732（≥2000px 长边） |

## 6. 色彩使用逻辑（五本册子的共同铁律）

| 角色 | 色值样本 | 用在哪 |
|---|---|---|
| **白 `#FFFFFF`** | 每本都是占比第一 | **所有常规内容页默认底** |
| **暖白/米白 `#F2EEE3` `#F3F0E9` `#F3EFE4` `#F7F4EF`** | 次高频 | 物料展示页——比纯白更暖、更"纸感" |
| **品牌主色** | 三餐里 `#4BCB04` / 小耕班 `#DE6E3C` / 摘山语 `#E6212A` / 蘑菇围炉 `#EA502C` / 鸽子官 `#EC6722` | **只出现在**：封面、章节页、宣言页、尾页 |
| **暗底 `#1D191A` `#342C2A` `#525451`** | 少量 | 空间氛围、灯光效果、重点价格页 |

**一句话逻辑**：`白 = 内容` → `暖白 = 物料` → `主色 = 章节骨架` → `暗底 = 氛围高光`。
主色是**节拍器**，不是背景板——它出现即代表"翻章了"。

## 7. 这条母版链的工作流

```
图片素材（设计稿）
      ↓
按页型归位：封面 / 序言 / 宣言 / 速览 / 章节 / 内容 / 尾页
      ↓
内容页选子版式（①②③…⑧）
      ↓
套母版骨架（页眉 + 留白 + 垂直居中）
      ↓
导出 PDF（16:10 + @page 锁尺寸）
```

> 落到本项目：`html-ppt` 产线负责承载，但**页眉页脚必须按本规范手写**——`html-ppt` 自带版式没有这套页眉。

---

## 8. 铁律

1. **不设页码**（模板 A 连页脚都没有）
2. **页眉线位置全册锁定**，不因页面内容多少而浮动
3. **章节页必须满版主色**，是唯一的"翻章"信号
4. **内容页不撑满**，垂直居中，宁可留白
5. **画布 16:10，不是 16:9**
6. **Logo/标识类仍走矢量精绘**，母版只负责"摆"，不负责"生"

## 9. 渲染实现铁律（HTML 落地专用 · 2026-09-17 补充）

> 第 1–8 节讲的是**版式几何**（母版长什么样）。
> 这一节讲**代码落地**——规范抄对了、CSS 也"看起来对"，仍然会整页崩。
> 以下每条都是实际踩过、调试数小时后才定位的。

### 铁律 R1 · 满幅层一律写死 `height:100%`，绝不只靠 `inset:0`

**坑**：`.deck` 上有 `transform: scale(var(--deck-scale))` 做视口适配。
**带 transform 的祖先会成为包含块**，此时 Chrome 对子元素 `bottom:0` / `inset:0`
的「拉伸到父高」解析**失效**——计算样式里 `top:0; bottom:0` 全对，
但盒高仍收缩为内容高度（实测 `.deck` 高 1080px，`.slide` 只有 **144px**），
满版主色页只剩顶部一条。

```css
/* ✅ 正确 */
.slide   { height:100%; }
.dv-wrap { position:absolute; inset:0; height:100%; }
.bleed   { position:absolute; top:-72px; left:-96px; right:-96px; bottom:-72px;
           height:calc(100% + 144px); }

/* ❌ 错误：只写 inset:0 —— 会被 transform 祖先打垮 */
```

**诊断佐证**（探针实测）：
```
deck  rect.h = 1080        ← 父元素正常
slide rect.h = 144         ← 子元素塌了
slide top=0 bottom=0       ← 计算值全对但没生效
force height:1080px  -> 1080  ✅
deck transform:none  -> 1080  ✅   ← 直指 transform 是元凶
```

### 铁律 R2 · 内容容器必须显式 `left/right: var(--mx)`
`.slide` 自带 `padding:72px 96px`（左右 96px ≈ **5%**），而版心 `--mx` 是 **11%**。
内容容器若不显式设 `left/right`，会继承 padding 起点而**比页眉更靠左**，
直接压住竖排边款（边款在 `--mx − 62px`）。
**页眉 / 正文 / 页脚三者必须共用 `--mx` 一条竖线。**

### 铁律 R3 · 不要给 `.slide` 写 `padding:0`
`.slide` 的 padding 是版心的一部分。归零会让整页内容消失。
要让内容超出 padding（满幅）用**负 margin**（见 `.bleed`），不要动 padding。

### 铁律 R4 · 出口锁尺寸
```css
@page{ size:1920px 1080px; margin:0; }
```
否则 PDF 落 Letter 白边。导出后**必须核对** `MediaBox` 比例是不是目标比例。

### 铁律 R5 · "计算样式全对但渲染不对" → 立刻上探针，别再读 CSS
这是最隐蔽的一类 bug。**用 `04-知识沉淀/工具/probe-box.js` 量 `getBoundingClientRect`**，
一次就能定位。死读 CSS / 二分注释会浪费数小时（本次就是这么耗掉的）。

### 铁律 R6 · 小体积 PNG ≠ 空白页
墨底满幅页因纯色压缩率极高，**20–40KB 是正常的**（本次修好后的分隔页也只 33KB）。
**别用文件体积判断"是否空白"** —— 要看内容，或拼联系表通读。

### 铁律 R7 · 固定画布下，尺寸一律硬编码 px（2026-09-18 新增）
满幅层、图台、图片限高**统统写死 px**，不用 `%`。
**根因**：图片写 `max-height:100%` 时，若容器高度由 `flex`/`stretch` 推导而来
（而非显式指定），Chrome 会**拒解这个百分比**、退回 `auto` →
图片按**原始像素尺寸**渲染并溢出容器被裁；导出 PDF 时甚至整张不画。
**实测**：1254px 的 Logo 在 1200px 宽的图台里裸奔被裁，PDF 里完全空白。

### 铁律 R8 · print 媒体查询里必须补 `overflow:hidden`（2026-09-18 新增）
`@media screen` 里写的 `overflow:hidden` **在 print 下不生效**。
任何溢出 1080px 画布的元素都会挤出一页 → **PDF 页数 = slide 数 + 1**（末页近空白）。
导出后**必核「PDF 页数 == slide 数」**，这是抓这条的唯一手段。

### 铁律 R9 · 「看起来不对」也要先量，**且先确认「看」的这张图有没有被缩放**（2026-09-18 强化）

读缩放后的显示图目测，会**系统性出错**。这条已被反复验证：

| 目测结论 | 实测结果 |
|---|---|
| 「图片溢出画布被切掉」 | 像素 + DOM 双证：图台 y∈[178,1000]、图片 y∈[230,948] 完全符合设计（那段"溢出物"其实是 `box-shadow` 投影） |
| 「图片溢出图台被裁」 | 图片 718×718 完全在图台内 |
| 「说明文字只占容器一半宽」 | 实测文字宽 **579**，设计值 584 |
| 「图片显示得太小」 | 原图元素占比反推 **717.0**，设计值 718 |

**根因**：读图工具返回的是**缩放后的预览**（1920px 图压到约 1094px 显示），
在缩放图上目测像素边界，误差被系统性放大。

**三个可交叉验证的量法**：
1. **像素法** —— PIL 扫包围盒。**必须限定扫描区**：首扫没排除页眉朱红编号与右侧小标题，
   得出荒谬的 1280px
2. **DOM 法** —— 注入脚本读 `getBoundingClientRect`（**先移除祖先 transform，见 R11**）
3. **反推法** —— 原图某元素占比已知 → 从截图反推渲染尺寸

**判据**：先量，再改。拼接核查图被压得过小时，改裁切局部看原尺寸。

### 铁律 R10 · 批量插入/替换脚本，收尾复核必须**双向**（2026-09-18 新增）

替换类脚本的复核要**同时**验两件事：
① **新标记已按预期数量加上** ② **旧标记仍按预期数量存在**。

**实测教训**：给 11 个案页批量插说明栏时，正则
`<div class="art-box">(?P<img>.*?)</div>` 捕获的是 `art-box` **内部**内容，
替换模板却漏写了外层包裹 → 图片裸挂、尺寸规则整条失效、按原始尺寸 1254px 溢出。
而收尾复核只数了三个**新增** class（`op-body` / `desc-label` / `desc-text` 全 = 11），
看着"很完整"，**没数被吃掉的 `art-box`（应为 11、实为 0）** —— 给自己发了张假通行证。

**判据**：只验新增项 = 没验。旧标记的数量必须一起核。

### 铁律 R11 · DOM 测量前先摘掉祖先 `transform`（2026-09-18 新增）

`.deck` 带 `transform:scale()` 做视口适配时，`getBoundingClientRect()` 返回的是**视觉尺寸**
（已乘 scale），"除以 scale 还原"这一步会引入两次量化误差 —— 实测偏大 **6px（724 vs 718）**。

```js
deck.style.transform = 'none';      // 改完直接读，getBoundingClientRect 会自动触发 reflow
var w = img.getBoundingClientRect().width;   // 此时即 1:1 布局真值，无需换算
```

摘掉后立得 **718.0 × 718.0**，与设计值分毫不差。
**要量布局值，就先把影响布局的 transform 摘掉；缩放还原只作兜底，不作判据。**

### 验收操作口径
渲染 / 导出**一律走 `04-知识沉淀/工具/render-deck.py`**（渲染 + PDF + 产物核对一体）。
它跑完会强制报「成功数 / 未生成页 / 体积偏小页」，**不许只看退出码**。
诊断疑难布局用 `04-知识沉淀/工具/probe-box.js`（量 `getBoundingClientRect` 真值）。
**凡是"退出码 0 + 文件确实生成了，但内容是错的"，一律按本节 R7–R11 逐条排查。**

## 10. 交付分支：主人要 `.pptx` 时怎么办（2026-09-18 新增）

本母版是 **HTML/CSS** 实现，出口是 **PDF**。但主人有时点名要 **`.ppt` / `.pptx` 文件**。

**不要**把 HTML 渲染成图再满幅塞进 pptx —— 那样每页只是死图，客户改不了字，
等于把 pptx 降级成 PDF。**要交付 pptx 就原生构建。**

```
母版几何（本文件 §1 §2）  ──1px = 9525 EMU 直落──▶  python-pptx 原生构建  ──▶  .pptx
                                                          ↓
                                             LibreOffice → PDF → PyMuPDF 渲图
                                                          ↓
                                                  像素扫描比对设计值
```

- 完整规范：**`04-知识沉淀/PPTX原生构建规范.md`**
- 骨架模板：**`04-知识沉淀/工具/deck2pptx.py`**
- 换算三式：`EMU = px × 9525` ｜ `pt = px × 0.75` ｜ `line_spacing = css_lh / 1.2`
- 本母版的几何常量（`--mx:11%` / `--hdr:15%` / `1360×850` / 不设页码）**原样适用**，
  两边同源，改一处要同步另一处。

> ⚠️ 该分支的验收**不用** `probe-box.js`（那是 DOM 探针），
> 改用 **PDF 渲染 PNG + PIL 像素扫描**；且 **PDF 探针报的 bbox 不可作几何判据**
> （含过渡带，系统性外扩约 4.2px）。
