# 能力注册表

> 蜂王拆完 DAG 后，为每个任务节点匹配执行方时查这张表。**随使用持续补充。**

## 使用规则

1. 按「任务特征」找最匹配的类别 → 直接用对应能力；
2. 无匹配 → 判断该路由给哪只工蜂，或标注【待路由】由蜂王自己处理；
3. 发现好用的组合 / 踩过的坑 → 追加到文末，越用越准。

## 七、已验证的好组合

**组合 1 · 品牌 logo 设计落地**（2026-09-11 梅湖小院，首单实跑 · **V2 已修正产线**）
```
用户基础信息（名称/城市/人均/面积/风格/主打品）
  → W2 品牌策略分析（定位 · 客群 · 调性关键词 · 设计禁区）
  → W2 三套差异化设计方向（理念/符号/配色/字体）
  → W3【矢量精绘产线】手写 SVG → resvg 光栅化多尺寸 → 单色 / 反白 变体
  → W3 逐张目视复核 + 三项检验（32px 可辨 / 单色立得住 / 深底反白可用）
  → W4 六项清单 + Logo 专项（含可单色性、缩放下限）
  → 交付：SVG 源文件 + PNG 多尺寸 + 单色 + 反白 + 提案展板 + 报告（字体建议 + 商标风险）
```
**关键经验**：
- ⚠️ **标识类任务禁用 AI 生图**。生图产出的是"渲染插画"，天然带渐变/柔光/装饰 → 会被判定为「辅助图案 / 灯箱效果」整单退回（2026-09-11 实战）。见踩坑库。
- 策略阶段产出的「设计禁区」（忌高冷/繁复/撞脸）是后续选图的硬标准，必须有
- 中文字标**不要交给 AI 直出**，图形标（矢量）+ 开源字体排版建议的组合才可靠
- 矢量 Logo 的四项专业硬指标：**纯平涂零渐变 · 可单色 · 32px 可辨 · 真矢量可缩放**
- 工具链：`04-知识沉淀/工具/矢量Logo工具链/`（`svg2png.js` / `make-sheet.py` / `make-board.py`）
- A 线生图 prompt 必带：`no text, no letters, no watermark, no signature, no mockup, no 3D`

**组合 2 · 真实交付册的结构盘点**（2026-09-16 餐饮 VI 物料/场景盘点，资料类首单实跑）
```
存量素材盘点（原图 + 联系表 + 结构解析 + 版面度量）
  → 【关键】找"出品方自带的分类标签"（本单：联系表保留的原始页眉栏目文字）
  → 逐页目视通读联系表，建「页码/栏目/画面/归类」四列索引
  → 定义统一归类口径 + 边界规则（本单：含空间要素→场景；纯底稿陈列→物料）
  → 【硬规矩】Python 从明细重算全部统计，正文只引用脚本输出
  → W1 子 agent 并行跑行业基准检索（提供对照口径）
  → W4 守卫蜂独立复算 + 页码证据抽查（≥15 处）
  → 返工修正 → 交付：主报告 + 提案速查清单
```
**关键经验**：
- ⚠️ **汇总量化指标必须跑脚本，不许估值**。本单唯一的高严重度错误（占比区间写 79%~92%，实为 66.7%~78.6%）就出在这一步。见踩坑库。
- **优先找"原作者的分类标签"**：真实交付册的页眉栏目、章节名往往就是最可靠的分类依据，比事后猜准得多
- **逐页标注不宜拆给多个 agent**：口径一致性是这类任务的命门，跨册同一物料必须归同类，拆开必漂
- **对照行业清单时，"我方有 / 行业没有"与"行业有 / 我方没有"要分两张表出**——反差本身就是最有价值的结论
- W1 子 agent 检索 + 主线程读图，是可并行的稳定组合（互不依赖）

**组合 3 · 多源对撞法**（2026-09-16 餐饮 VI 联网扩样，第二轮实跑 · **适用于一切"用数据说话"的调研题**）
```
① 先定统一码本（把上一轮的分类骨架扩成"外部样本也能填"的字段表）
      ↓ 码本不统一，外部数据聚合不起来——这一步必须在派工前完成
② 派 N 只侦查蜂，按【来源域】切分并行（互不重叠）
     本单：A 公开案例（站酷/古田路9号/奖项）｜B 商业报价（猪八戒/Fiverr/Upwork）｜C 渠道规范与行业规模
      ↓ 每只蜂的 prompt 里内嵌同一份码本 + 统一字段表 + 硬指标数量
③ 主线程不采信工蜂自报统计表 → 用脚本从「样本总表」原始行重抽码复算
      ↓ 复算能查出"列内统计错"，但查不出"列本身漏抽"（见下）
④ W4 守卫蜂：URL 可点性抽查 + 条目真实性抽查 + 行业数据反查 + 独立复算
      ↓ 守卫蜂的价值在"实际联网核实"，不是文本比对
⑤ 三源判定：>0 记「有」/ ≥15% 记「强」→ 三源共振 / 我有外弱 / 我缺口 / 单源 / 三源皆无
⑥ 返工 → 交付（提案版 + 详版 + 可视化矩阵）
```
**关键经验**：
- ⚠️ **口径不可比就必须先声明**：本单三源分别是「页次占比 / 提及率 / 覆盖率」，报告开篇即写明"只比排序与有无，不比绝对值"，否则整篇结论都是误读。
- ⚠️ **上游人工抽取的中间列 = 「下界」**：本单 T5B「覆盖 M 码」列人工挑拣、漏抽 3 项，导致 M12 判定从「单源」升级为「我缺口」。**下游复算会全盘继承该漏抽** → 该列一律标「下界/至少」，且结论方向要论证"偏差只会加强而非削弱"。
- ⚠️ **跨行去重计数必脚本**：6 处手算错误全部集中在"几行里有几行含 X"这类活上。
- **"镜头朝向"比"谁对谁错"更有价值**：真实差异往往不是数据错，而是三个源各自展示偏好不同（交付册重内容物料 / 作品集重视觉冲击 / 报价单重标准化）。**把这个差异本身讲清楚，就是最硬的结论。**
- **反差清单是最值钱的产出**：按"我方独有 / 我方缺口 / 三源共振 / 三源皆无"分四档，直接对应提案的四层报价结构（必做层 / 差异化层 / 补课层 / 独占层）。
- **来源域必须切干净**：三只蜂若都去搜"餐饮VI设计"，会撞车并重复；按平台域切分才能拿到独立样本。

**组合 4 · 数据驱动的清单生成器模式**（2026-09-16 完整物料清单 T8，第三轮实跑 · **适用于一切"带数据背书的清单/名册/标准"交付**）
```
① 取上游已验收的数据码表（本单：T6 三源对撞表 24 个 M/S 码）
      ↓ 码表是"数值唯一真源"，后续所有数字都从它取
② 【关键】结构与数值分离：
     人工定义「清单结构」（项名 / 归类 / 建议规格 / 依据备注）
     脚本持有「数值码表」并负责填充
      ↓ 改归类不碰数值，改数值不碰结构——两者永不手抄混写
③ 写生成器脚本 → 一次产出多版本（蜂巢详版 + 工作区提案版）
      ↓ 脚本内置自检：未知码检测 + 码表覆盖完整性 + 分层自动汇总
④ W4 守卫蜂验收（本轮重点：**依据出处逐条回原表抽查**，不只看聚合数字）
      ↓ 抽 18 处依据，抓出 1 处"编造的依据"（把 A 案例的能力安到了 B 案例头上）
⑤ 返工 → 逐处串行改 → 重跑 → **grep 产物**双向复核（新标记在、旧标记无）
⑥ 交付：详版（含边界与验收留痕）+ 提案版（可直接套用）
```
**关键经验**：
- ⚠️ **清单里的"数据背书"列不许手写**：全部由脚本从上游码表填充。本单 88 项 × 三源 ×24 码，手抄必错。
- ⚠️ **守卫蜂查"依据"比查"数字"更能抓到错**：聚合数字有脚本兜底，反而安全；**"依据"是自然语言，最容易凭记忆编**——本单唯一高严重度问题正是「声称某案例有数字适配，回查该案例根本没有」。
- ⚠️ **上游判定口径不一致要显式收敛并留痕**：本单发现 T6 汇总表把 S7（5.3%/0%/0%，仅我方一源有）误归「我有外弱」，按 T6 自定规则应为「单源」。**不静默复制，而是在新文档里写明"对上游做了一处口径收敛"**，类目归属不变、仅标签修正。

- **分层汇总由脚本算**，正文只引用脚本输出——与组合 2/3 同一条硬规矩。
- **跨版本产物要一起重跑**：改了生成器就重跑全部版本，别只更一个，否则两版数字会漂。

- ⚠️ **`.deck` 的 `transform` 是最大暗雷**：它使满幅层 `inset:0` 拉伸失效，

- ⚠️ **小体积 PNG ≠ 空白页**：墨底满幅页 20–40KB 属正常，别拿体积当判据。
- ⚠️ **「看起来不对」也要先量，且先确认「看」的图有没有被缩放**：
  读图工具返回的是**缩放预览**（1920px 压到约 1094px），在缩放图上目测边界误差被系统性放大。

- ⚠️ **量 DOM 前先摘掉祖先 `transform`**：`deck.style.transform='none'` 再读 `getBoundingClientRect()`，
  否则带 `scale()` 的 deck 让测量值偏大（实测 **724 vs 718**）；摘掉后精确得 718.0。
- ⚠️ **批量插入/替换脚本收尾必须双向复核**：既数**新标记**（应加上的）、**也数旧标记**（应保留的）。

**关键经验**：
- ⚠️ **pptx 的立身之本是可编辑**。凡是"渲染成图再塞进去"的做法，都是把 pptx 降级成 PDF，
  客户一改就露馅。**要交付 pptx 就老老实实原生构建。**
- ⚠️ **PDF/图像探针报的 bbox 不能当几何判据**：`page.get_image_info()` 把描边与抗锯齿过渡带
  算进外接框，系统性**外扩约 4.2px** → 本轮据此误判「图台间隙从 22 缩到 13.6」「比例条色块重叠」

- ⚠️ **像素扫描前必须先定位元素行位**：本轮首扫直接按设计坐标扫，落在**行距空隙**上"扫了个空"，
  误以为该处无内容。正确姿势：先大阈值扫全页逐行暗像素数 → 定行位 → 再精扫边界。
  （行距会让文字整体下移约 19px，设计坐标 ≠ 扫描坐标）
- ⚠️ **中文字体必须写 `a:ea`**：`run.font.name` 只写 `a:latin`，中文会回退宋体。
- ⚠️ **标志素材是白底不透明 RGBA**：做反白/深底场景前必须去背，且**只能用四角洪水填充**——

- ⚠️ **字体页不许伪造字标字体**：标志字标多为定制毛笔书法体，字库里没有长得像的。
  如实写「定制书法体 + 使用规则」，**不要拿楷体/行楷冒充**，也不要从标志上裁字（本轮实测：
  字标与人物形象交叠，根本裁不出干净的一块）。
- **标注"主色来源"**：AI 生成图没有品牌色票，色值是**提取推定**的，
  必须在手册里写明来源（"取自标志主视觉的朱红"），别伪装成品牌方给定值。
- **图片重复插入不会膨胀文件**：python-pptx 按 SHA1 去重 ImagePart
  （本轮 logo-壹 出现 4 次，pptx 仍只有 3.27MB）。
- **形状记得关阴影**：`add_shape` 继承主题阴影，须 `shadow.inherit = False`。
- **单行文字用 `MIDDLE` 锚点**，多行段落用 `TOP` + 估算框高，抗估算误差。
