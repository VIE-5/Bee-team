## 二、内容铁律（交付物层面）

| 铁律 | 内容 |
|---|---|
| 生图硬规矩 | 零水印、零 Logo、零文字（逐张肉眼确认） |
| **事实源优先** | 任何规范／物料类交付，**第一个动作是通读品牌事实源**（BrandLock 所在单）。品牌主色、口号、调性、文案一律以事实源为准；**标志内部色（如墨 `#2D301B`、印章红 `#DE1C19`）不参与物料色板**。反面教材：2026-09-19 土蚝小院规范第一版把标志墨色当品牌主色、自创深墨绿、自拟母题与口号 → **整版作废**。根因是"先做后验" |
| **样张零编造** | 排版样张可以放占位，但**绝不许编造真实内容**（菜名、价格、地址、电话）。正解：灰条占位 + 图注声明「须替换为主人提供的准确文字」。依据：BrandLock §6「新增文案必须主人提供」 |
| **变体稿着色** | 反白稿／单色稿的着色一律取**品牌色板色**，**不得从"参考件"实测色出发** —— 否则资产与对比度矩阵会出现两套口径 |
| **最小尺寸反推法** | 由最细结构线反推最小印刷宽度时，**必须用「双向游程 + alpha>200」**（水平测竖线宽 / 垂直测横线粗），并**写明取哪个分位、为什么**。实测下限取整后留余量。屏幕下限另需**真的缩到目标尺寸看一眼**，不许系数推算 |
| **产线路由（W3）** | **标识 / Logo / 图标 / 字标 / 印章 → 矢量精绘（手写 SVG），禁用生图**；氛围图 / 插画 / KV / 配图 / 情绪板 → 生图。判错产线 = 整单退回 |
| Logo 交付四硬指标 | 纯平涂零渐变 · 可单色 · 32px 可辨 · 真矢量可缩放；必交 SVG 源文件 + 多尺寸 PNG + 单色 + 反白 |
| 中文字标 | 不给 AI 直出（必出伪字），只出图形标 + 开源字体排版建议由人工排 |
| **反白稿双色互换** | 做标志反白稿（深色载体用）**必须**用「双色互换」：按亮度二值化，**暗部→白、亮部→本版主色**，alpha 原样保留。⛔ **禁止**把可见像素全涂白——那只是一坨**无结构白块**，深底载体上全废。判据：**生成后必合成到深底目视** |
| **模板复用的规矩** | 「**套模板 ≠ 模板没问题**」。复用旧版式时必须按验收清单**整册重过一遍**；发现缺陷**一律回写母版与规范**——只改本单 = 下一单原样再踩 |

### 3.2 多方案展示册 · 三版式

主人给**参考版式截图** + 明示「不用其余页面」→ 走**原生 pptx 三版式**：
① 详页（左标志台 + 右「标志构成」三段 + **色彩应用并入同页**：等宽色卡承色值 + 分宽条承配比，窄段 <72px 不标 %）
② 并置页（多版**等宽**并排 + 编号/名称/场景）
③ 载体应用页（**矢量绘制**门头灯箱/碗盖/木牌/围裙/名片，**深底必配反白稿**，双卡**并排别重叠**）

铁律：**去背图必先 trim 透明边**；色卡文字色按底色明度选。探针用 `工具/probe-pptx.py`。
参考：`碗香\Logo一-全案封装\`（5 页）。

### 3.3 交付物分支

主人点名要 **`.ppt` / `.pptx`** → 走 **python-pptx 原生构建**（`04-知识沉淀/工具/deck2pptx.py` + `PPTX原生构建规范.md`），**禁止「HTML 渲染成图再塞进 pptx」**——那是死图，客户改不了字。

- 换算三式：`EMU = px×9525`｜`pt = px×0.75`｜`line_spacing = css_lh / 1.2`
- 中文字体必须写 `a:ea`（只写 `font.name` 中文回退宋体）
- 验收链路：LibreOffice→PDF→PyMuPDF 渲图→**PIL 像素扫描**
- 参考实现：`贵州遵义\碗香\Logo一-全案封装\`（14 页 · 3.27MB）

### 3.4 社媒 KV 定式

- **竖版 1080×1920**：文字落画面自带的浅色留白；底部实色带只用来盖住 UI 遮挡区，**绝不用实色带横盖画面中下段——会把菜盖掉**
- **横版 1920×1080 左文右景**：左栏 486px 岩米纸底＝独立图层承 Logo+副标+口号，右侧照片满幅。照片裁切**先量产品物理边界再定刀口**
- **规范页＝一页制 A4**（1600×2880 设计+S=2 超采样；**长句按栏宽自动收字号 `Tfit`，禁 `s[:n]` 切片**；HEX 别用 Consolas）

### 3.5 图片素材 → 册子封装（A 全案）· 2026-09-19 跑通

**做法**（土蚝小院品牌全案 25 页）：

1. `prep.py` 把每张原图加工成一张 1920×1080 满幅页：
   - **底层**＝原图 `cover` 铺满 + 高斯模糊（≈58px）→ **模糊铺底**，色彩连续无接缝
   - **前景层**＝原图 `contain` 居中（**一刀不裁**，原素材常四角带字）
2. 实测每页页眉带 / 页脚带的平均亮度 → 写进 `meta.json`
3. `build.py` 按数据表生成 25 页 HTML（cover / toc / section / art / end 五种页型）
4. CSS 按亮度自动切页眉页脚字色（深底→暖米白、浅底→墨色）与遮罩方向
5. `render-deck.py --sheet` 出 PNG + 联系表，`--pdf` 出交付 PDF

**画幅选择**：与原素材主画幅一致（本单 16:9，原图 1672×941 → 内容区 1667×938，**近似 1:1，零缩放损失**）。
若画幅不一致，小字密集页（规范表、色卡值）会糊。

## 四、几何与渲染铁律（排版类任务派工必下发）

| 代号 | 铁律 |
|---|---|
| **R1** | 满幅层写死 `height:100%`，**绝不只靠 `inset:0`** —— 带 `transform` 的祖先是包含块，会让 `bottom:0`/`inset:0` 的拉伸解析失效（计算样式全对、盒高塌成内容高） |
| **R2** | 内容容器必须显式 `left/right:var(--mx)` —— 否则继承 `.slide` 的 padding，比版心更靠左，压住竖排边款 |
| **R3** | 不给 `.slide` 写 `padding:0`；满幅请用负 margin |
| **R4** | 锁 `@page{size:...;margin:0}`，导出后核对 MediaBox |
| **R5** | 疑难上探针（`工具/probe-box.js`）别读 CSS |
| **R6** | 小体积 PNG ≠ 空白页（墨底满幅页 20–40KB 属正常） |
| **R7** | **固定画布下尺寸一律硬编码 px** —— `%` 在 flex/stretch 推导高度的容器里会被 Chrome 拒解 → 图片按原始尺寸溢出 |
| **R8** | `@media print` 里补 `overflow:hidden !important`（否则溢出内容分页，**PDF 页数 = slide 数 + 1**） |
| **R9** | 「看起来不对」也**先量再改**，且先确认"看"的这张图有没有被**缩放**（读图工具返回的是缩放预览） |
| **R10** | **批量插入/替换脚本收尾必须双向复核**（数新标记 **+** 数旧标记），只验新增项 = 假通行证 |
| **R11** | 量 DOM 前先摘掉祖先 `transform`（`deck.style.transform='none'`），否则带 `scale()` 的 deck 让测量值偏大 |
| **R12** | **页面容器 class 必须走独立命名空间（`pg-*`）**，严禁与组件/行级 class 同名 —— 撞车会让页面几何被污染：打印端整页下推 → **PDF 多一页**；屏幕端改掉 `display` → **截图全同**。命名前先 `grep "\.<候选名>" theme.css` 确认零命中；print 块对 `.slide` 的 `margin/padding/border` 一律 `!important` 硬化（2026-10-10 实证，一个根因两个症状） |
| **R13** | 「一对多」归属的登记表（章节页码、批次索引、分组映射）**键必须带归属维度**（如 `(篇, 节号)` 而非 `节号`），否则后一个分组会取到前一个分组的页码 |
| **R14** | **目录 / 索引类交付必做逐行回验**：不能只验「生成了 N 行」，要把每行标注值与**实际页位**比对，输出 `错行数 / 总行数`。同理，「页数 == slide 数」之外**再核分片流里各 `.slide` 的 `top` 是否为 `n × 画布高`**（连续无跳变）—— 这是「页面几何被污染」的机检出口 |
| **R15** | **版式一改，浏览器实测尺寸的缓存立即作废**：`card_heights.json` / `--measure` 回传值是分页预算的**唯一依据**，改任何影响卡高/元素高的 CSS（字号、行高、内边距、增删元素）都**必须重跑 `--measure` → `run_measure.py` 再重建**。否则「预算用旧高、内容是新高」→ **整册静默溢出**（2026-10-10 实证：改「分条」版式未重测即会踩；已在 build 里留 `--measure` 步骤并写进派工单勾选项） |
| **R16** | **删页 / 改名 / 调序后，页码基准与署名落点必须同步重算并回验**：页脚 `NN/总` 的起点、目录页码基准、`TOTAL` 三者互锁，**改一处漏一处就是整册页码错位**（2026-10-10 实证：改基准时漏改目录页自身 `page_no` → 全册页码从 3 起跳）；改名/删尾页类改动若动了**署名承载页**，必须回头核「作者·作品名·来源·许可」四件套落点数 **> 0**（删尾页≠可丢署名） |

**其他排版坑**：

- `<figure>` 带 UA 默认 `margin:1em 40px`，做网格项不 reset 会**静默掉列**
- 改完 CSS 重渲染画面不变 → **先怀疑 Chrome 缓存**（URL 加时间戳）
- 输出符号别用 `✓✗⚠`（GBK 直接崩脚本），也别把 stdout 转 UTF-8（中文全乱码）
- **同目录旧交付名会被误发**：改版/改名后旧 PDF 仍留在同目录（甚至被预览面板锁住无法移动）→ 交付前先归档旧产物到 `_archive_rN/`；`mv` 报 `Device or resource busy` 即被预览面板占用，须请主人关闭预览
- **Georgia 是老式数字字体**：`03` 会渲染成 `o3`。页码/编号必须 `font-variant-numeric:lining-nums; font-feature-settings:"lnum" 1`
- **模糊铺底的取代关系**：照片/渐变类页面的补边，**禁止**用「边缘条带拉伸」（会拉出横条纹，像图挂了）→ 一律用 `cover + 高斯模糊`

**Windows 渲染**：

- 统一走 `04-知识沉淀/工具/render-deck.py`（渲染 + PDF + 拼联系表 + **强制产物核对**），**不要用 `.bat`**
- Chrome headless **必须带 `--user-data-dir`**，否则静默失败；**必须带 `--force-device-scale-factor=1`**（防 DPI 缩放把 1920×1080 截成 1094×929）
- **调外部程序一律传 Windows 风格路径 `C:/...`** —— Git Bash 只对纯 ASCII 路径做 Unix→Windows 转换，蜂巢路径含 `——` 与中文 → 转换被跳过 → 静默零产出（退出码仍为 0）、进程僵死占锁；`-env:UserInstallation` 指向纯 ASCII 临时目录
- **产物核对**：「命令退出码 0」≠「任务成功」，收尾必数数量 + 看体积

## 七、关键约束

- **平台未开放 TeamCreate** → 工蜂不是常驻进程，是「角色卡 + 文件总线」，这是整套架构的地基，别试图改成真进程。
- 专家中心需主人手动切换，蜂王不能自动拉起。
- 引入开源/技能/API 前，守卫蜂必须过「引入审查五问」：安全 / 许可 / 维护 / 成本 / 替代。
- **否决方向禁止增量修补**（2026-10-06 立规，源自 `brand-system-skill` 规则 19）：
  当一个方向被否决后，**不许在它上面改**。四条基础系统（整体调性 / 字体系统 / 主色逻辑 / 材质语言 /
  包装架构 / 视觉层级 / 摄影方向 / 客群适配 / 感知价格档次）**命中 ≥2 项即判定「推倒重建」**，不是"调整"。
  重建纪律：① 标记旧稿 `REJECTED — 不得再作视觉参考`　② **只保留抽象决策**（KEEP 列表）
