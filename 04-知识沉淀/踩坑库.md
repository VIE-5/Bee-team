### 2026-09-11 · AI 生图默认水印（首单实战踩坑）

- **场景**：梅湖小院 Logo 生图，3 张中 2 张（B、C）右下角出现「AI生成 WORKBUDDY」水印
- **现象**：与 prompt 里的 `no watermark` 强约束冲突，属于模型层默认行为
- **根因**：
  1. 该生图通道会在右下角固定位置叠加水印，与提示词无关
  2. 工具参数 `footnote` 本是水印字段，传空格无效，无法关闭
- **解法（已验证）**：**裁切补偿**——探测水印顶边 → 裁掉底部 + 左右对称补齐保持正方形 → 无损放大回原尺寸。
  - 优点：**不涂抹、不遮盖**，画面内容零损伤，无修图痕迹
  - 参数：水印顶边约 y≈967（1024 图），裁底部 71px + 左右各 35px
- **⚠️ 检测陷阱**：水印是**浅灰细字**，用「行平均色差」判定会被稀释导致漏检（首版脚本就栽在这里）；必须用**行内最大色差**（阈值 ≈30），且扫描区要避开画面主体
- **防复发**：已写入 `02-工蜂/图片施工蜂.md` 作业标准第 1 条；工具沉淀为 `04-知识沉淀/工具/clean_logo.py`

### 2026-09-11 · 选错兵器：把「logo 设计」当「生图任务」做（整单退回）

- **场景**：梅湖小院 Logo 交付，W3 用 `ImageGen` 出了 3 版位图，全链路验收评级 B 放行
- **现象**：客户（主人）退回，评语——「**未达餐饮设计 logo 标准，更像辅助图案，以及软布灯箱的设计效果**」
- **根因（三层）**：
  1. **工具属性错配**：AI 生图产出的是"渲染插画"——天生带径向柔光/渐变/笔触/场景氛围，而餐饮 logo 的标准是**纯平涂、零渐变、零阴影、几何精准**
  2. **图形不凝练**：生图会堆砌装饰，产出的形可被无限平铺复用 → 那是**辅助图案**（辅助图形），不是**标识**
  3. **缺专业检验项**：V1 验收只查了"有没有水印、清不清晰"，**没查"能不能单色用、缩到 32px 还认不认得出、有没有几何精度"**
- **解法（V2 已验证）**：**换兵器——矢量精绘**
  - 手写 SVG 路径（自己算坐标，100% 可控），再光栅化为多尺寸透明 PNG
  - 一次性解决四件事：零水印（源头规避）+ 纯平涂无渲染 + 真矢量可缩放 + 可单色
  - 工具链：`04-知识沉淀/工具/矢量Logo工具链/`（`svg2png.js` / `make-sheet.py` / `make-board.py`）
- **路由判据（写死，别混）**：

  | 任务类型 | 该走哪条道 |
  |---|---|
  | **标识 / Logo / 图标 / 字标 / 印章** | **矢量精绘（手写 SVG）** |
  | 氛围图 / 插画 / KV / 配图 / 情绪板 | AI 生图 |
  | 去水印 / 修图 / 抠图 / 增强 | 图像处理工具 |

- **防复发**：
  1. 已写入 `02-工蜂/图片施工蜂.md`——新增「矢量精绘」通道，作业标准第 0 条立为路由判据
  2. 已写入 `01-蜂王/派工单模板.md` 的产出形态栏：标识类必须标注"矢量交付"
  3. **验收清单 Logo 专项**加两条：**可单色性** + **32px 可辨性**

### 2026-09-11 · 同文件多处修改并行提交相互覆盖（工具使用坑）

- **场景**：新增 W5 设计提词蜂，需同步更新 6 份章程共 15 处表述
- **现象**：同批次发出的多处编辑**互相覆盖**，最终只有 6 处生效——`README.md` 4 处只落 1 处、架构理解 V1 4 处只落 1 处、能力注册表 3 处只落 1 处。逐处 grep 才查出漏改
- **根因**：同一文件的多个编辑若在**同一批次并行提交**，各自基于同一份原始快照计算替换结果，后写入者覆盖先写入者
- **解法**：**同一文件的多处修改必须串行** —— 每轮只对同一文件发一处编辑；**不同文件之间可以并行**
- **防复发**：改动落地后**必须 grep 复核关键标记**，不许凭「编辑返回成功」就认定生效
