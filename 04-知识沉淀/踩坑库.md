```markdown
- **解法**：怎么绕过去 / 修好的
- **防复发**：写进哪个角色卡的哪条 / 哪份清单要加什么
```

### 2026-09-11 · AI 生图默认水印（首单实战踩坑）

- **场景**：梅湖小院 Logo 生图，3 张中 2 张（B、C）右下角出现「AI生成 WORKBUDDY」水印
- **现象**：与 prompt 里的 `no watermark` 强约束冲突，属于模型层默认行为
- **根因**：
  1. 该生图通道会在右下角固定位置叠加水印，与提示词无关
  2. 工具参数 `footnote` 本是水印字段，传空格无效，无法关闭
- **解法（已验证）**：**裁切补偿**——探测水印顶边 → 裁掉底部 + 左右对称补齐保持正方形 → 无损放大回原尺寸。
  - 优点：**不涂抹、不遮盖**，画面内容零损伤，无修图痕迹
  - 参数：水印顶边约 y≈967（1024 图），裁底部 71px + 左右各 35px
- **⚠️ 检测陷阱**：水印是**浅灰细字**，用「行平均色差」判定会被稀释导致漏检（首版脚本就栽在这里）；必须用**行内最大色差**（阈值 ≈30），且扫描区要避开画面主体
- **防复发**：已写入 `02-工蜂/图片施工蜂.md` 作业标准第 1 条；工具沉淀为 `04-知识沉淀/工具/clean_logo.py`

### 2026-09-11 · 选错兵器：把「logo 设计」当「生图任务」做（整单退回）

- **场景**：梅湖小院 Logo 交付，W3 用 `ImageGen` 出了 3 版位图，全链路验收评级 B 放行
- **现象**：客户（主人）退回，评语——「**未达餐饮设计 logo 标准，更像辅助图案，以及软布灯箱的设计效果**」
- **根因（三层）**：
  1. **工具属性错配**：AI 生图产出的是"渲染插画"——天生带径向柔光/渐变/笔触/场景氛围，而餐饮 logo 的标准是**纯平涂、零渐变、零阴影、几何精准**
  2. **图形不凝练**：生图会堆砌装饰，产出的形可被无限平铺复用 → 那是**辅助图案**（辅助图形），不是**标识**
  3. **缺专业检验项**：V1 验收只查了"有没有水印、清不清晰"，**没查"能不能单色用、缩到 32px 还认不认得出、有没有几何精度"**
- **解法（V2 已验证）**：**换兵器——矢量精绘**
  - 手写 SVG 路径（自己算坐标，100% 可控），再光栅化为多尺寸透明 PNG
  - 一次性解决四件事：零水印（源头规避）+ 纯平涂无渲染 + 真矢量可缩放 + 可单色
  - 工具链：`04-知识沉淀/工具/矢量Logo工具链/`（`svg2png.js` / `make-sheet.py` / `make-board.py`）
- **路由判据（写死，别混）**：

  | 任务类型 | 该走哪条道 |
  |---|---|
  | **标识 / Logo / 图标 / 字标 / 印章** | **矢量精绘（手写 SVG）** |
  | 氛围图 / 插画 / KV / 配图 / 情绪板 | AI 生图 |
  | 去水印 / 修图 / 抠图 / 增强 | 图像处理工具 |

- **防复发**：
  1. 已写入 `02-工蜂/图片施工蜂.md`——新增「矢量精绘」通道，作业标准第 0 条立为路由判据
  2. 已写入 `01-蜂王/派工单模板.md` 的产出形态栏：标识类必须标注"矢量交付"
  3. **验收清单 Logo 专项**加两条：**可单色性** + **32px 可辨性**

### 2026-09-11 · 同文件多处修改并行提交相互覆盖（工具使用坑）

- **场景**：新增 W5 设计提词蜂，需同步更新 6 份章程共 15 处表述
- **现象**：同批次发出的多处编辑**互相覆盖**，最终只有 6 处生效——`README.md` 4 处只落 1 处、架构理解 V1 4 处只落 1 处、能力注册表 3 处只落 1 处。逐处 grep 才查出漏改
- **根因**：同一文件的多个编辑若在**同一批次并行提交**，各自基于同一份原始快照计算替换结果，后写入者覆盖先写入者
- **解法**：**同一文件的多处修改必须串行** —— 每轮只对同一文件发一处编辑；**不同文件之间可以并行**
- **防复发**：改动落地后**必须 grep 复核关键标记**，不许凭「编辑返回成功」就认定生效

### 2026-09-15 · Git Bash 不转换含中文/破折号的路径 → 外部程序静默失败 + 进程僵死

- **场景**：VI 案例母版拆解任务，用 LibreOffice headless 批量把 5 个 PPTX 转 PDF
- **现象（两个，相隔几小时才串起来）**：
  1. 后台转换任务「跑完了」但 `00-原始PDF/` **一个文件都没有**——静默零产出
  2. 数小时后主人手动双击 LibreOffice 图标，弹出**「配置文件 bootstrap.ini 已经损坏」**
- **根因**：
  1. **Git Bash(MSYS) 只对纯 ASCII 路径做 Unix→Windows 转换**。蜂巢路径含 `——`（em dash）与中文，
     MSYS 放弃转换 → LibreOffice 实际收到 `-env:UserInstallation=file:////d/WORK——Vie/...`、
     `--outdir /d/WORK——Vie/...`、源文件 `/d/360MoveData/...` 这类**非法路径** → 找不到文件、
     连输出目录都不合法 → **退出码仍是 0，但零产物**
  2. LibreOffice 是**单实例**程序：这次启动的 headless 实例一直僵死不退，占着配置目录锁。
     主人再手动启动时新实例抢不到锁，LibreOffice 把「锁冲突」**误报成「bootstrap.ini 已损坏」**——
     **配置文件其实是好的**（112 字节、内容完全标准，见下）
- **误报实测证据**：`C:\Program Files\LibreOffice\program\bootstrap.ini` 内容
  ```
  [Bootstrap]
  InstallMode=<installmode>
  ProductKey=LibreOffice 26.2
  UserInstallation=$SYSUSERCONFIG/LibreOffice/4
  ```
  → 完好。**别信这个报错，先查进程。**

- **解法**：
  1. 杀僵死进程：`Stop-Process -Id <soffice.exe/soffice.bin> -Force`（`taskkill //F` 在 Git Bash 里 `//F` 会被原样传入而失败，改用 PowerShell）
  2. **给外部 Windows 程序传路径必须用 Windows 风格**（`C:/...`），不要指望 Git Bash 转换中文路径
  3. `-env:UserInstallation` 一律指向**纯 ASCII 临时目录**，如 `file:///C:/Users/<u>/AppData/Local/Temp/xxx/prof`
  4. 修好后**实测验证**：转一个小文件，PDF 正常产出 + 无残留进程 = 健康
- **验证结果**：改正路径后转 `in.txt` → 出 PDF 13915 字节、退出码 0、无残留进程、「bootstrap.ini」报错不再出现

- **⚠️ 副产物教训**：那次批量转换失败后我**没有核对产物就往下走了**。虽然本任务后来改走
  `ppt/media` 直接提取原图（效果更好），但**「命令退出码 0」≠「任务成功」**——
  有产出的任务必须**核对产物存在与数量**。这是比路径问题更该记的一条。

- **防复发**：
  1. 已写入 `04-知识沉淀/工具/html-ppt-使用手册.md` 的 Windows 坑清单
  2. **凡是「跑外部程序产出文件」的命令，收尾必查产物**：`ls` 数数量、比体积，不看退出码
  3. 用外部程序前先想一句：**它认得这个路径吗？** 中文 / 破折号 / 跨盘符 → 一律换 Windows 风格路径
