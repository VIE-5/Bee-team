# 蜂群体系 · V1 → V2 差异对账

> 日期：2026-10-13 · 起草：旺财 🐶 · 状态：**待主人确认**
> 基准 = 体系自身。「V1」取 `蜂群架构理解-V1.md` + `蜂群全景图-V1.html`（2026-09-11 初建快照）；
> 「V2」取 `蜂群体系全景图-V2.html`（2026-10-13 现状）。**所有"实际有无"结论均经磁盘实扫核验。**

---

## 零、一句话结论

**V2 是 V1 的「大扩容 + 大沉淀」**——从「骨架 + 角色」长成「产线 + 铁律 + 组合 + 工具链」的作战体系；
但扩容过程中 **丢了 V1 的三块方法层**（实现路径 / 决议记录 / 独立静默准则），且 **V2 自称的工具链有 2 件是"幽灵"**。

## 二、V2 相对 V1 的六大增量（进步）

1. **W3 四产线** —— 像素活拆成 A 生图 / B 矢量精绘 / C 排版封装 / D PPTX 原生，「判错产线 = 整单退回」是多重任务优化最硬的沉淀。
2. **W4 四模式** —— 守卫蜂从「挑刺」升级为 产出审查 / 引入审查（五问）/ 发布审 / 排版专项验法。
3. **R1–R16 十六铁律** —— 每条对应一次真实事故（满幅塌页、class 撞车、目录错行、页码互锁…），V1 完全没有这一层。
4. **组合 1–8** —— 实跑过的完整链路库，新任务先来这找最接近的一条照做。
5. **六层架构图 + 能力交互图** —— V1 只有目录树，V2 给出「指令怎么流、闸门卡在哪」的视觉表达。
6. **承接边界三档** —— 稳定接单 / 有条件接单 / 接不了，把「能干什么」说清楚了。

## 三、V1 有、V2 遗漏的三项（回退点）

| # | V1 内容 | 为什么该捡回来 |
|---|---|---|
| **A1** | **工蜂三种实现路径**：A 路由式（蜂王切角色）/ B Skill 式（推荐主力）/ C Fork 子 agent（重活，成本高要「信任但核实」）+ **建议配比** | 这是「工蜂**怎么落地**」的方法层。V2 只讲「是什么」，没讲「哪只蜂用什么姿势跑」。C 路径的**成本警告**也一并丢了 |
| **A2** | **决议记录表**（静默 / 五蜂 / 三档 / Git 单主干 4 项拍板 + 落地位置） | 变更追踪的锚点。V2 用「演进时间线」讲了**过程**，但没给「**当前仍然生效的决议**」清单，后人不知哪些是拍过板的 |
| **A3** | **静默准则独立成章**（三触发条件 + 一行卡片例外） | V2 压成蜂王卡里一行。细则（≤3 问、每个带推荐项、一行卡片例外）散失了 |

## 四、V2 自身的可优化细节（**经磁盘核验**）

### 🔴 P0 — 幽灵工具（硬伤）

V2「技能与工具池」表宣称工具链 **8 件**，但实扫 `04-知识沉淀/工具/` 全目录后：

| V2 宣称 | 磁盘实际 | 结论 |
|---|:---:|:---:|
| render-deck.py | ✅ 存在 | OK |
| probe-box.js | ✅ 存在 | OK |
| probe-pptx.py | ✅ 存在 | OK |
| probe_fit / probe_overflow | ✅ 存在（在 `deck-benchmark/` 子目录） | OK |
| deck-benchmark | ✅ 存在 | OK |
| **geo-budget.py** | ❌ **全仓 zero 命中** | ⚠️ 幽灵 |
| **deck-audit.py** | ❌ **全仓 zero 命中** | ⚠️ 幽灵 |

→ **8 件里 2 件查无此物。** 组合 8 里「先算几何预算」「deck-audit 终检」对应的脚本也没落盘。
**处置**：要么补脚本，要么把 V2 清单改成实存项，并标注这 2 项为「计划中 / 待固化」。

### 🟡 P1 — 真实工具被漏列

V2 工具链表**没提**这些实存脚本：`clean_logo.py`、`png-color-pick.py`、`render-win.bat`、`矢量Logo工具链/`（svg2png.js · make-sheet.py · make-board.py · lockup.py）、`deck-benchmark/` 里的 `probe_geom / probe_blocks / probe_structure / compare5 / make_ab / parse_source`。
→ 工具链的「实际边界」比 V2 画的大，建议对齐。

### 🟡 P1 — 「14 单」口径不准

实扫 `03-任务档案/`：**14 个任务目录**，但含 `00-任务图.md`（走完三件套的凭证）的**只有 11 个**。
缺任务图的 3 个是调研/分析类：`brand-system-skill全面分析`、`开源Adobe生态整合分析`、`GitHub高性价比人生指南调研`。
→ 建议统一口径：**「14 个任务档案 · 11 单走完三件套」**（现 V2 在 header / 沉淀层 / 演进线三处都写 14，需一并改）。

### 🟢 P2 — render-win.bat 残留未标废

工具目录仍存 `render-win.bat`，但制度已定「统一走 render-deck.py，不要 .bat」。V2 未标注其作废状态 → 建议在能力注册表标「已弃用」。

### 🟢 P2 — 缺「已知冲突」标注

记忆里挂着「`command-center` 与 `swarm-queen` 职责重叠待归拢」，而 V2 直接把 `swarm-queen` 写成蜂王入口。
→ 建议在技能池补一行「⚠️ 与 command-center 职责重叠，待归拢」。

### 🟢 P2 — 展示层未与「实测」互链

V2 是**设计意图**图；`蜂群体系关系分析-V1.html` 是**实测依赖网**。两者应互链（V2 补一句「实际耦合见关系分析」），否则又落入「展示层与运转脱节」的老坑。
