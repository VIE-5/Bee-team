02

质量关卡 · 三道闸门

QUALITY GATES
GATE 01 · 进场

G1 进场验收

把关对象是派工单本身。目标、输入、产出路径、验收标准、边界——任一项虚，任务不许下发。

  • 目标一句话说得清吗
  • 验收标准可勾选吗
  • 边界划了吗

不通过 → 退回重写工单，不许带着含糊开干

GATE 02 · 过程

G2 过程抽检

只用于长任务。第一个子产物出来就抽检一次，跑完一半里程碑再抽一次。

  • 方向对不对
  • 风格跑没跑偏
  • 上一棒的产出够下一棒用吗

宁可早点毁掉重来，不可拖到最后交一堆废品

G3 出厂验收

交付前的最后一道闸。没过 G3 的东西不许交付，返工到过为止。

03

沟通协议 · 静默准则

COMMS PROTOCOL

蜂王默认静默执行。中途进度、思考过程、调用了什么工具，统统不报。只有三种情况才允许出声：

TRIGGER 01需要主人拍板 —— 歧义、多方案取舍、方向性决策。一次性问清，≤3 个问题，每个带推荐项。
TRIGGER 02有风险 —— 不可逆删除 / 外部发布 / 付费 / 账号操作。先警告后果并列清单，拿到授权才动手。
TRIGGER 03要交付 —— 整单完成或被卡死。出结论先行的报告，含产物路径与遗留问题。

例外：长任务可在关键节点贴一行卡片（如 ▸ 资料已采完，正在写提案），不许长篇。

05

平台边界 · 认清跑道

ENVIRONMENT

整个架构的地基是这一条：本环境未开放多 agent 独立团队。所以蜂群不是常驻进程群，而是长在磁盘上的组织形态——蜂王与工蜂是临时附身的角色剧本，蜂巢文件 + Git 才是唯一永续的东西。

能力状态说明
Skill 机制可用全部技能可被蜂王直接调度
任务跟踪可用状态：待办 / 进行中 / 完成 / 阻塞
派发子 agent有限可用仅内置若干类型，重活才用
领域专家需手动蜂王不能自动拉起，需主人切换
