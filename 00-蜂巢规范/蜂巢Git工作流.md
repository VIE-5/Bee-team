# 蜂巢 Git 规范

> 单人 + AI 团队的极简版本流。目标：**能回退、能溯源**，不要复杂的分支仪式。

## 分支策略

**只有一个主干：`main`。** 不开分支、不搞 merge 仪式。

理由：这个蜂巢是主人一人的项目空间，分支带来的管理成本远大于收益。真要试验性大改，拷靴整个产物目录另存为止巳。

## 什么时候提交

| 时机 | 提交吗 |
|---|---|
| 每单任务**完成**且验收单已落盘 | ✅ 必提交（一单 = 一次提交） |
| 任务进行中的中间产物 | ⚠️ 可提交，标 `wip:` 前缀，方便中途回退 |
| 蜂巢章程 / 角色卡更新 | ✅ 提交，标 `doc:` |
| 整理文件、删废稿 | ✅ 提交，标 `chore:` |
| 每个工具调用之后 | ❌ 绝对不要，会产生垃圾历史 |

## 提交信息格式

```
{类型}: {一句话简述} ({日期})
```

| 类型 | 用在哪 |
|---|---|
| `task` | 一单任务的完整产出与验收 |
| `wip` | 任务进行中的中间存档 |
| `doc` | 蜂巢章程、角色卡、验收清单等文档更新 |
| `asset` | 新增/替换素材与产出物 |
| `fix` | 修正历史提交中的错误 |
| `chore` | 整理、清理、结构调整 |

示例：
```
task: 土蚝院子视觉解构提案初稿过验 (2026-09-11)
doc: 确立四只工蜂编制与验收三档严格度 (2026-09-11)
```

## 大文件策略

Git 不适合存大二进制。约定：

- **单文件 < 10MB** → 正常入库（pptx / docx / png 多数在此范围）
- **单文件 10-50MB** → 斟酌，建议入库但同目录留 `_资产清单.md` 说明
- **单文件 > 50MB**（长视频、分层素材）→ **不入库**，改为在同目录维护 `_资产清单.md`，记录文件名、大小、生成参数与外部存放路径

`.gitignore` 已自动排除：系统垃圾、编辑器临时文件、依赖目录、日志、PSD/AI 等巨型源文件。

## 安全红线

- **禁止提交**：API Key、Token、密码、账号信息、私钥
- 需要用密钥时写进 `.env`（已在忽略列表），**蜂巢内只保留 `.env.example`**
- 提交前想一下：这份文件如果明天被别人看到，会不会出问题

## 常用动作

```bash
# 看历史（一行版）
git log --oneline

# 撤销未提交的改动
git restore <文件路径>

# 回退到某次提交
git checkout <commit-id> -- <文件路径>

# 看某文件改了什么
git diff <文件路径>
```

**回滚前先看清影响范围。** 涉及已交付成果的回滚，蜂王必须先向主人报告。
