# 蜂群架构理解 V1

> 日期：2026-09-11 · 起草：旺财 🐶 · 状态：**待主人确认**

## 一、一句话理解

主人要的是一支**「一个脑子 + 几双手」的小团队**：蜂王不干活、只动脑（听懂任务 → 拆成活儿 → 派给对的蜂 → 盯着进度 → 验货 → 打包交付），工蜂不动脑、只干活（各管一段专业活），全队靠**共享文件夹（蜂巢）**串起来，而不是靠各自的记性。

## 二、先摸清家底：当前环境能做什么 / 不能做什么

设计之前必须先认清楚跑道宽度，别画一张落不了地的图。

| 能力 | 现状 | 备注 |
|---|---|---|
| Skill 机制 | ✅ 完全可用 | `~/.workbuddy/skills/`，已有 command-center 等 20+ 技能 |
| 任务跟踪工具 | ✅ 可用 | TaskCreate / TaskGet / TaskUpdate / TaskList |
| 派发子 agent | ✅ 可用（有限） | 内置类型：general-purpose / Explore / Plan / sheet-agent / doc-\* 系列 |
| 并行执行 | ✅ 可用 | 多条互不依赖的任务可同一轮并行发起 |
| 专家中心 | ⚠️ 半自动 | 需主人手动切换专家，不能由蜂王自动拉起 |
| 自由组建多 agent 团队 | ❌ 暂不支持 | 本次会话未开放 TeamCreate，只有一个隐式团队通道 |
| 工蜂长驻后台 | ❌ 天然限制 | 子 agent 跑完即散，需要靠**文件**当记忆延续 |

**这条「❌」决定了整个设计的走向**：真正的"蜂群"不是一个常驻进程，而是**一套放在磁盘上的组织形态**——蜂王和工蜂都只是被调用时临时附身的"角色剧本"，蜂巢（文件）+ 公约才是唯一永续的东西。这样设计的好处是：换个会话、换个模型，只要蜂巢还在，团队就还在。

## 三、角色定义

### 3.1 蜂王 Queen（唯一的大脑）

| 项 | 说明 |
|---|---|
| 定位 | 指挥家 + 质检员。**不抢活**，只做无法委派的事 |
| 输入 | 主人的自然语言指令（可以很含糊、很粗糙） |
| 六步工作流 | ① 接单复述 → ② 拆 DAG → ③ 能力路由 → ④ 派发跟踪 → ⑤ 验收把关 → ⑥ 聚合交付 |
| 输出 | 一份任务图 + 一份验收单 + 一个打包好的交付物 |
| 硬规矩 | 出现不可逆 / 外部发布 / 付费操作，必须先问过主人再动手 |

### 3.2 工蜂 Workers（五只，可按任务扩编）

> 已按主人拍板的编制实体化，角色卡见 `02-工蜂/`

| 编号 | 角色 | 干什么 | 手上兵器 | 验收重点 |
|---|---|---|---|---|
| W1 | **资料侦查蜂 Scout** | 找东西：搜索、抓网页、读文件、公众号采集、事实核实 | WebSearch / WebFetch / agent-browser / 采集脚本 | 来源可溯源？时效标了吗？存疑有没有藏？ |
| W2 | **提案筑巢蜂 Builder** | 造结构化的交付物：PPT 提案、Word 文档、Excel 表格、网页 | tencent-pptx / docx / sheetagent / logo-analysis-ppt | 零占位符？数据有出处？字体可商用？ |
| W3 | **图片施工蜂 Image** | 造像素：生图、视频、3D、去水印去文字、品牌延展、表情包 GIF | ImageGen / VideoGen / buddy-image-processing / brand-extension | 零水印零 Logo 零文字？有畸形吗？分辨率够吗？ |
| W4 | **守卫蜂 Guard** | 挑刺：六项清单审查、引入开源的安全许可审计、发布合规、事实复核 | 审查清单 + Read + WebSearch 反查 | 问题标位了吗？建议可执行吗？有没有诚实标注未查范围？ |
| W5 | **设计提词蜂 Prompter** | 写词：把需求 / 方向翻译成可执行的设计 prompt 与 brief，**不产出成品** | 设计提词库（九字段结构 · 负向铁律清单 · 空词替换表） | 零空词？九字段齐吗？铁律清单挂了吗？ |

> 工蜂不是固定编制，是按任务**临时编组**的。一个简单任务可能只有一只蜂；一个复杂方案能同时飞出去五只。

> 工蜂不是固定编制，是按任务**临时编组**的。一个简单任务可能只有一只筑巢蜂；一个复杂方案能同时飞出去五只。

## 四、工蜂的三种实现路径（决定了"重量"）

| 方式 | 怎么落地 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| **A 路由式** | 蜂王自己切换角色模式干 | 零成本、最快 | 无上下文隔离，容易串行出力 | 单领域小活 |
| **B Skill 式** | 每类工蜂写成独立 SKILL.md，蜂王按名调用 | 可积累、可复用、团队会越来越聪明 | 要写配置 | **主力方式，推荐** |
| **C Fork 子 agent** | 用 Agent 工具 fork 出隔离上下文的专项蜜蜂 | 上下文干净、可真并行 | token 成本高、结果要"信任但核实" | 重调研 / 长文档 / 易污染的杂活 |

**建议配比**：日常 A 为主，成熟工种沉淀成 B，专项重活才上 C。

## 五、质量把关：三道关卡

这才是"蜂王"和"一个会说漂亮话的模型"的真正区别。

| 关卡 | 时机 | 检查什么 | 不通过怎么办 |
|---|---|---|---|
| **G1 进场验收** | 派活之前 | 每个任务是否写清了：目标 / 产出物 / 验收标准 / 边界 | 退回重写任务书，**不许带着含糊开干** |
| **G2 过程抽检** | 长任务中途 | 看中间产物，别等到最后才发现方向歪了 | 当场纠偏，已做部分决定是否报废 |
| **G3 出厂验收** | 交付之前 | 六项清单：完整性 / 准确性 / 格式 / 合规 / 可用性 / 一致性 | 打回返工（B 级小修 / C 级重做） |

**G3 六项清单**是所有工蜂通用的硬骨架，具体工种再挂自己的细则（比如生图类必查"零水印零 Logo 零文字"）。

## 六、蜂巢：团队的唯一记忆体

```
蜂王/
├── 00-蜂巢规范/      公约、流程、契约模板（团队的"法"）
├── 01-蜂王/          角色卡、派工单模板、验收清单
├── 02-工蜂/          各工蜂的角色卡与作业标准
├── 03-任务档案/      每单任务的完整留痕
└── 04-知识沉淀/      踩坑记录、好用的组合、能力注册表（越用越强）
```

**每次任务的档案三件套**（放在 `03-任务档案/{日期}-{任务名}/`）：

| 文件 | 谁写 | 内容 |
|---|---|---|
| `00-任务图.md` | 蜂王 | 指令原文 / 理解复述 / 假设清单 / DAG 任务表 / 执行日志 |
| `01-工蜂产出/` | 工蜂 | 各节点的原始产物，不改不删，留痕可追溯 |
| `02-验收单.md` | 蜂王 | G3 六项打分 + 返工记录 + 最终结论 |

## 七、落地路径（建议分三步，别一步到位）

| 阶段 | 目标 | 产出 |
|---|---|---|
| **P1 先跑通** | 蜂王 = 升级现有 command-center 技能，跑一单真实任务 | 一份能用的角色卡 + 一单完整档案 |
| **P2 补编制** | 把主人高频工种沉淀成 2-3 只正式工蜂 Skill | 侦查蜂 / 筑巢蜂 / 守卫蜂 角色卡落地 |
| **P3 自动化** | 任务图 → 派发 → 验收 → 沉淀 全链路半自动 | 蜂群可独立跑中等复杂度任务 |

## 八、决议记录（V1.1 · 主人已拍板 · 2026-09-11）

| # | 议题 | 决议 | 落地位置 |

| 2 | 工蜂编制 | **五只**：资料侦查蜂 / 提案筑巢蜂 / 图片施工蜂 / 守卫蜂 / **设计提词蜂**（W5 于 2026-09-11 按主人指示追加） | `02-工蜂/*.md` |
| 3 | 验收严格度 | 主人暂未定 → 采用**三档可切换**机制，默认「标准档」，判不出来就用标准档 | `01-蜂王/验收清单.md` |
| 4 | 是否接 Git | **接**。单主干 `main`，一单任务 = 一次提交 | `00-蜂巢规范/蜂巢Git工作流.md` |

### 关于第 2 项的澄清
主人原始名单中「提案筑巢蜂」出现了两次、且漏缺了「图片施工蜂」的位置，已按语义去重为四只。若实际需要两只提案筑巢蜂并行作业，随时可以增加编制 —— 工蜂本就是按任务临时编组的。

**后追加 W5 设计提词蜂**（2026-09-11 主人指示）：团队原本缺一层「翻译」—— W2 管「是什么 / 为什么」、W3 管「做出来」，中间的**「怎么说」无人负责**，导致 prompt 质量全凭临时发挥（梅湖小院首单即因产线判错走了一轮弯路）。W5 只出指令、不做成品，填的就是这一层。

### 关于第 3 项的说明
"目前不确定"是合理答案，所以给的不是固定值而是**档位开关**：

- **速查**（内部草稿）查 2 项 → **标准**（日常交付，默认）查 4 项 → **严查**（对外/客户/付费）查 6 项 + 专项条款
- 主人口头喊「切严查」「这单速查」即可切换
- 判不出来时一律用标准档，**不许自行放水**
