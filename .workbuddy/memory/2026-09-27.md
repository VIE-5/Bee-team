## 页眉带裁切的判定方法（本项目可复用）
三种自动判据全废（密集非白 / 纯白间隔 / 阈值目测），根因两条：
**背景是暖白非纯白**、**页眉带与内容间是稀疏区不是空白区**。
正解 = **认结构不认底色**：
1. 行剖面取「编号胶囊块（`cap_frac≥0.25`）」与「栏目标题行（暗≥0.15 且 中≥0.08）」两者的最大 y 作带底 `bb`；
2. 从 `bb` 往下跳过抗锯齿残尾，落到底色≥92% 的首行作 `cut`；间隔<6 行则 `bb+4` 标 `TIGHT`；
3. **底色自适应**（四边中位色，每通道容差 6），暖白底也能正确归类；
4. **裁后必出 1:1 边界复核图**（红线标裁切线，y=cut−40..cut+120）逐张目视，**禁止用缩略图定值/复核**；
5. **双向抽检**：顶部看残留 + 内容看是否裁多 + 底部规格栏完整性（32/32 完整）。

## 渲染/导出链路的三个静默失败
1. **中途截断但退出码 0**：55 页只出 49 页、PDF 与联系表未执行；因命令末端 `| tail -40`，
   管道退出码取 tail 的 0。**发现方式 = 逐张量产物规格**（抓到尺寸集合 `{(1360,850),(1920,1080)}` 混装）。
   → 收尾固定三步：**数数量 + 量规格 + 对时间戳**。
2. **PDF MediaBox 1.598947 ≠ 1.6**：**最小复现**定责 —— 单 div 页面（px/pt 两种声明）同得 637.92pt，
   且 1000px 高**精确命中** 750pt → 是 Chrome 打印引擎的**页面框离散步进量化**，与内容/CSS/单位无关。
   偏差 +0.42pt = 0.148mm（0.066%）逐页一致，**不判缺陷**。
3. **视口 ≠ 画布 → 截图带 `#8A8A8A` 灰边**：`render-deck.py` 硬编码 `--window-size=1920,1080`，
   16:10 画布只占中间一块。

## render-deck.py 三项参数化（已落 `04-知识沉淀\工具\render-deck.py`）
| 参数 | 默认 | 解决 |
|---|---|---|

## ⚠️ 本日最大教训：既有铁律的第二次复发

**现象**：渲染「成功 72/72、退出码 0、体积分布 30.5–1155.9 KB（差异显著）」三项全过，
但 1:1 目视发现 **P17 板图左缘文字被切**、**P70 主题海报只剩中间一条**。几何探针实测：
**22 张图被静默裁切**（板图 ×5 左右各 ≈260px；门帘/服装/营业时间牌/品牌故事/IP展示/F05/主题海报 ×4
竖版上下各 ≈230–495px；名片 73px、饮料杯 27px）。

**根因**：r3（已验证交付）用的是 **px 硬编码上限** `max-width:1054px; max-height:676px`；
r4 为"排版美观"包了层 `.frame` 并换成 **`max-height:100%`** ——
`.frame` 高度来自 flex 拉伸（**computed `height` 仍是 auto**），
而**百分比 `max-height` 的基准是包含块的 `height` 属性、不是 used value** → Chrome 解析为 `none`
→ 图退回原尺寸 → 被 `overflow:hidden` 裁掉。
**`max-width:100%` 因不依赖内容高度而仍生效 → 只有竖版图出事**，掩盖了问题。

**性质**：铁律 **2026-09-18 已立**（「固定画布下尺寸一律硬编码 px」，已写进 VI 母版规范 §9）。
本轮属于**未立项地"顺便升级"了一段已验证正确的实现**。

这三项在图片被裁时**全部正常**；联系表缩略图也看不出（竖版图被裁中间 35% 后，缩略图就是"一张横图"）。
**唯一能拦住的是几何量测。**

**修复**：回 px 上限 + `.frame{width/height:fit-content}` 让图版**贴合图片**；

海报页另立 `.slide.poster` **左图右栏**（海报满高 467×700）。

逐张图量「渲染尺寸 vs 容器 padding box」→ `CROP`/`DISTORT`/`COLLAPSE` → PASS/FAIL(n)。
