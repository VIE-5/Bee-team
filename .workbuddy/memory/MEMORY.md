# 蜂群项目长期约定

## 项目是什么
主人自建的小型 agent 团队「蜂群」。蜂王（指挥中枢）+ 四只工蜂，全部以 **Markdown 角色卡 + 蜂巢文件 + Git** 承载。
蜂巢根目录 = `D:\WORK——Vie\沃克巴蒂\蜂群\蜂王`（也是 workspace）。

## 已确立的制度（改之前先想清楚为什么改）

| 制度 | 内容 |
|---|---|
| 沟通准则 | 蜂王默认**静默执行**，只在「需主人拍板 / 有风险 / 交付或卡死」三种情况出声 |
| 工蜂编制 | W1 资料侦查蜂 / W2 提案筑巢蜂 / W3 图片施工蜂 / W4 守卫蜂 |
| 派单铁律 | 无派工单不派活，工单必须写全：目标 / 输入 / 产出路径 / 验收标准 / 边界 |
| 验收机制 | G1 进场查工单 → G2 长任务抽检 → G3 出厂六项（完整/准确/格式/合规/可用/一致）；评级 A 放行、B 小修、C 重做 |
| 严格度三档 | 速查 2 项（草稿）/ 标准 4 项（**默认**）/ 严查 6 项+专项（对外交付）；口头即可切换 |
| 归档三件套 | `00-任务图.md` + `01-工蜂产出/` + `02-验收单.md` |
| Git | 单主干 `main`，一单任务 = 一次提交（`task:` 前缀），单文件 > 50MB 不入库 |
| 生图硬规矩 | 零水印、零 Logo、零文字（铁律，逐张肉眼确认） |

- **平台未开放 TeamCreate** → 工蜂不是常驻进程，是「角色卡 + 文件总线」，这是整套架构的地基，别试图改成真进程。

- 引入开源/技能/API 前，守卫蜂必须过「引入审查五问」：安全 / 许可 / 维护 / 成本 / 替代。
- Office 文件必须走专用 tencent-* 技能，不许 Python 库生撸。
