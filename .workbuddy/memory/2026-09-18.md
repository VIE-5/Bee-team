## 关键决策：不套 HTML，改走 python-pptx 原生构建

主人要 `.ppt` 而不是 PDF，说明**要可编辑**。
把 HTML 渲染成图再满幅塞进 pptx 是死图，客户改不了错别字 → 等于把 pptx 降级成 PDF。
故新建产线：**把母版 px 几何 1:1 落进 PPT**。

**换算三式**（这是全套的地基）：
```
EMU  = px × 9525        （96dpi，母版所有 px 值可直落）
pt   = px × 0.75        （字号）
line_spacing = css_lh / 1.2   （PPT 单倍行距≈1.2×字号）
```

**本轮新增经验**：
- **每版色值按版独立聚类**（`quantize(14)` 取前 4 + 建议占比），比 v1 的单一主色推定值更实。

  多版并排大小明显不一。trim 后内容比例 0.991/0.968/0.986，并排自然等大。
- **「色彩应用」拆两件表达**：等宽色卡（承色值）+ 分宽条（承配比），窄段 <72px 不标 %。
- **载体示意走矢量绘制、不走生图**：矩形/圆角矩形/椭圆拼出门头、碗盖、木牌、围裙、名片；
  深底配反白稿、木色暖底配墨稿；木纹线先画后贴 logo，自然被遮。

### 复用中暴露并修掉的两处「模板自带缺陷」（**本轮最大收获**）
1. **反白稿是纯白剪影** —— 首单同款缺陷，当时逐页只看"骨架成不成立"没发现。
   表现为 P5 门头灯箱 / 员工围裙 / 名片红卡上标志成**一坨无结构白块**。
   根因：`所有可见像素转纯白` 抹平了内部明暗关系。
   改 **「双色互换」**：按亮度二值化，**暗部→白、亮部→本版主色**（alpha 不动）。
   阈值 128 安全：实测三版底色 luma 47~61，字与浅底 215~253，中间是真空区。
2. **三段释义段间距 −0.5px** —— `lh=1.9` + 段步进 119，段实占 119.5 → 三段粘连成一坨。
   改 `lh=1.62` + 步进 120 + 正文起 `yy+34`，实测段间距 ≈13px。

另修两处尺寸：门头灯箱板高 152→186（标志 114×120 → 158×166）、围裙 logo 110→94。
