### 体积优化（重要 · v5 已确立，v6 沿用）

首版按全册通用规范（长边 1920）重制素材 → PDF **129.5 MB**，超主人此前拍板的「折中 ~70MB」。

探测 PDF 内嵌对象后定位根因：
- Chrome `--print-to-pdf` 以 **`/FlateDecode`（无损）** 嵌入图片，**不做降采样** → 图像对象全是素材原始像素，占文件 99%
- **PDF 体积由素材像素线性决定**，与打印倍率无关

据此按**显示尺寸**定制素材分辨率：
- 物料图显示宽 = 1060.8（v5 为 521.4）CSS px
- 1920px → 353 dpi（过剩 2.4 倍）；**1200px → 221 dpi**（印刷优质档，屏幕 2× 仍锐利）
- 29 张物料素材统一取 **1200 长边**（1200×900，合计约 5.6MB）

结果：首版 **129.5 MB → 90.7 MB**。

### 三项硬性约束的落实

| 要求 | 落地方式 |
|---|---|
| **不拼图 · 独立展示** | 每张物料独立成图 + 独立题注（`<figure>` + `<figcaption>`），彻底取消拼贴位图 |
| **禁止页眉页脚冲突** | 图片全部限制在内容区内（`top:--hdr / bottom:10% / left,right:--mx`），页高几何可算、零重叠 |
| **禁止景深渐变** | **不设任何 scrim / mask / gradient / box-shadow**；仅 1px 实线边框 + 纯色底 |

## 六、学习项（已回写知识沉淀）

| 学习项 | 落点 |
|---|---|
| **满幅图页去遮罩后，页眉必压图** → 图片必须限制在内容区内，不能铺满画布 | `04-知识沉淀/踩坑库.md` |
| **`--force-device-scale-factor` 对 `--print-to-pdf` 无效**（scale=1 与 2 输出完全一致）；**PDF 体积 100% 由图片分辨率决定，文字始终是矢量** | `04-知识沉淀/踩坑库.md` |
| **中文字距/行高应建刻度变量**，行内硬编码 `.06~.44em` 会让全册节奏散掉 | `04-知识沉淀/踩坑库.md` |
| `--force-device-scale-factor=2` **对 `--screenshot` 有效**（可出 2× 高清截图） | 已写入 `_中间文件/render-one.py` 注释 |
| **批量 `str.replace` 改样式前，必须先按页面边界审计归属** —— 相同 DOM 结构会跨页无差别命中（本轮误伤 P15/P16/P26） | `04-知识沉淀/踩坑库.md` |
| **换图必须同步核算几何**：比例变化会改变可用高度，窄列里放 4:3 图会撑不住版面（P05 实测） | `04-知识沉淀/踩坑库.md` |
| **PDF 体积与页数无关**：45 页 → 60 页（+33%）而体积**完全相同**（均 90.7 MB），再次证明体积只由图片像素总量决定，纯文字页只贡献矢量开销 | `04-知识沉淀/踩坑库.md` |
| **素材展示密度默认「一物料一页」**：全案册篇幅不构成成本，单张物料的呈现面积才是交付价值；组合并置是「省页数」思路，容易牺牲清晰度 | `04-知识沉淀/踩坑库.md` |
