## 八、踩坑记录（待回写 `04-知识沉淀/踩坑库.md`）

### 坑① 固定尺寸 deck 用 `#/N` 截图 → 全部同一屏
- **现象**：37 张 PNG 体积完全一致（938.2 KB），md5 全同
- **根因**：`render-deck.py` 靠 `<uri>#/<N>` 让 Chrome 跳到第 N 页，依赖 deck 自带 `runtime.js` 监听 hashchange。本册是母版规定的「多张固定 .slide 纵向平铺」结构，**没有 runtime.js** → hash 被忽略 → 每次都截到第一屏
- **解法**：写 `render-one.py` —— 每页生成独立临时 HTML（只留该页 .slide）+ 逐张量体截图
- **防复发**：收尾**必须做 md5 唯一性核对**，`唯一内容数 == 页数` 才算过。体积"太整齐"就是可疑信号

### 坑② 文件名骗人：`logo-白.png` 不是反白稿
- **现象**：贴到深底 logo 完全看不见
- **根因**：该文件实为「透明底 + 墨色标志」（白底稿），文件名里的"白"指白底。实测 alpha 90% 透明、可见像素白 0% / 暗 9%
- **解法**：以它为唯一来源，**双色互换**生成反白稿（墨部→暖白 #F3E8D2，**印章红保留**）
- **防复发**：文件名不可信，**必须白底/深底各合成一次肉眼核对**（对照图存 `_中间文件/_logo-variants-check.png`）。这正印证 BrandLock §2「反白稿必须双色互换」——涂白会得到无结构白剪影

### 坑③ 临时页相对路径：图片静默 404
- **现象**：截图里页眉/页脚/文字/色块全对，**只有图片是碎图占位符**
- **根因**：临时页放 `_pages/` 子目录，只改写了 `<link href>` 为 `../assets/`，**漏改 `<img src="assets/">`** → 浏览器去 `_pages/assets/` 找 → 404
- **解法**：所有资源引用统一改写为**绝对 file:// URI**
- **防复发**：加 `verify-images.py` 探针，读 DOM 的 `naturalWidth`，`=== 0` 即失败。**不许只靠肉眼看截图找碎图**
