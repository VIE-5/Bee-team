# Stage 1 — Reference Deconstruction（参考解构）

> **前置说明**：skill 的硬性输入是「1 张主视觉参考」。主人尚未提供 →
> **本演示采用 skill 自己的规则 2（不编造）**：把参考解构的**分析框架**做出来，并**用策略事实源里的「新中式庭院风」作为待解构目标的占位**，明确标注 `【参考图待补】`。

## 分析框架（12 维，skill 原生）

| # | 维度 | 对「新中式庭院风」的**推定**解构 `【参考图待补，以下为框架演示】` |
|---|---|---|
| 1 | 核心创意张力 | 都市 vs 田园 —— 在城里造一个"院" |
| 2 | 构图与网格 | 对称 / 框景（月亮门、窗棂取景） |
| 3 | 视觉层级 | 留白主导，主体退居一隅 |
| 4 | 字体行为 | 楷/宋的骨，现代无衬线的肉 |
| 5 | 色彩行为 | 低饱和自然色 + 一点暖（烟火气） |
| 6 | 摄影/插画取向 | 自然光、材质特写（木/石/陶/水） |
| 7 | 光照与材质 | 侧逆光、漫射；青砖、原木、藤编 |
| 8 | 留白规则 | 大面积呼吸感，**但不可冷** |
| 9 | 标志性图形装置 | 框景 / 水纹 / 枝影 |
| 10 | 主体摆放 | 偏置、非正中（避免祠堂感） |
| 11 | 情绪基调 | 雅而不贵、鲜而有烟火 |
| 12 | 可规模化campaign原则 | 一景一菜，构图族恒定、内容可换 |

## 关键切分（skill 的核心动作）

### ✅ Transferable Principles（可迁移原则）
- 对称构图与框景手法
- 低饱和自然色 + 局部暖色
- 材质特写的摄影语言
- 大面积留白（**但必须注入暖意**）

### ❌ Source-Specific Elements（**禁止抄袭**）
> skill 明令：不得复制专有 logo、包装、字体、宣称、插画、角色、纹样、品牌专属图形资产

- 任何具体餐厅的 logo 形制与组合
- 任何具体的窗棂/砖雕纹样原件
- 别家的菜单版式与装饰边框
- **"梅花 + 圆形徽章"的通用组合** ← 主人自己的策略里已列为禁区（忌撞脸）

### 🔄 Translation Opportunity（转译机会）
> 主人策略给的三个视觉富矿：**「梅 + 湖」「院」「鱼」**

| 富矿 | 转译方向 | 禁区 |
|---|---|---|
| 梅 + 湖 | 疏影、水纹、朦胧层次 | 忌撞"梅花+圆徽章" |
| 院 | 框景、月洞、天井、老树（**符号库**） | 忌繁复堆叠窗棂 |
| 鱼 | 辅助符号，可做动势 | **不得与"梅湖"主符号争注意力** |

### 🎯 Creative-Direction Statement（一句话创意方向）

> **"以院的框，养湖的鲜，落梅的影 —— 一座可以去吃的院子。"**
> 视觉上做「**有暖意的留白**」：骨架是新中式的克制与秩序，血肉是烟火气的暖色与手作质感。

# Stage 3 — Creative-Direction Review（创意方向审计）

## 按 skill 的 10 条审计标准，对本项目做预设审计

| # | 审计项 | 预判风险 | 等级 |
|---|---|---|---|
| 1 | 是否传达**一个**方向？ | 三套 Logo 案若混用 → **必然分裂** | 🔴 |
| 2 | 是否存在多种视觉语言竞争？ | 「梅」文人感 vs 「鱼」食材感 若同权重 → 竞争 | 🟠 |
| 3 | 层级是否清晰？ | 待实测 | 🟡 |
| 4 | 材质与图形是否一致？ | 待实测 | 🟡 |
| 5 | 图标/纹样/装置是否过多？ | **主人策略已预警「忌繁复」** | 🟠 |
| 6 | 字体是否支撑定位？ | 楷书易滑向"高冷"，与人均 60 冲突 | 🟠 |
| 7 | 包装架构是否可识别？ | 待定触点 | 🟡 |
| 8 | 留白是否足够？ | 中餐馆通病：塞满 | 🟠 |
| 9 | 能否跨 SKU/规格规模化？ | 需验证"一景一菜"构图族 | 🟡 |
| 10 | **是否有源品牌身份泄漏？** | ⚠️ **主人已明确「忌撞脸：梅花+圆徽章」** | 🔴 |

## 三份清单（skill 原生输出格式）

### KEEP — 最强的系统定义元素
- 「小院」带来的**符号库**（院 / 框 / 树 / 天井）—— 这是品牌名的神来之笔
- 「雅而不贵、鲜而有烟火」的**调性双轴**
- 「梅湖烧鱼」的**单品爆款记忆锚点**

### REMOVE — 制造杂乱或碎片化的元素
- 多重边框与雕花窗棂堆叠（**缩到 64px 必糊**）
- 与「梅」主符号**争权重**的鱼形装饰
- 纯黑白水墨的冷调处理（**与人均 60 冲突**）

### REFINE — 该留但需更清晰的规则
- 「鱼」符号：**降为辅助**，明确其尺寸与位置规则
- 暖色：**建刻度**（主暖 / 次暖 / 点缀），不许随手取色
- 留白：**建档位**（疏 / 中 / 密），不许凭感觉

## 🔥 REFINE vs REJECT AND RESTART 判定演示

> 这是 skill **最锋利**的一刀，用一个**真实场景**演示它怎么用：

**场景**：主人看了首版提案后说 —— *"感觉不对，太像茶室了，不像吃饭的地方。"*

**蜂王的判定过程**：

| 检查项 | 命中？ |
|---|---|
| 整体调性 / 美学被质疑 | ✅ **命中** |
| 摄影方向偏了（茶室感） | ✅ **命中** |
| 目标客群适配被质疑（不像餐厅） | ✅ **命中** |
| 感知价格档次偏了（茶室=更贵） | ✅ **命中** |

**→ 触及基础系统 4 项 → 判定为 `REJECT AND RESTART`，不是 REFINE。**

> **判据原话**：*"Use REJECT AND RESTART when the feedback changes several foundational systems."*

**若主人说的是** ⬇️
> *"整体对，就是那个暖色再压一点，另外 logo 在门头小了。"*

| 检查项 | 命中？ |
|---|---|
| 一个色值 | ✅ |
| 一处尺寸问题 | ✅ |
| 其余基础系统 | ❌ 均未触及 |

**→ 判定为 `REFINE`。**

## 重启五步（若走 REJECT 分支）

```text
1. 标记旧板面 → REJECTED — DO NOT USE AS A VISUAL REFERENCE
2. 只保留 KEEP 里的抽象决策（院符号库 / 调性双轴 / 单品锚点）
3. ⛔ 不得把被否决的板面作为生成参考附上
4. 从零构建（基于已批简报 + 参考解构 + 新方向陈述 + 已批字体系统）
5. 生成前先出 Generation Plan
```

> 🔥 **skill 规则 19 在此处生效**：
> *"Never blend a rejected direction with a replacement direction."*
> **理由（原文）**：混用会导致**混合字体、残留材质、矛盾颜色、视觉伪影**。
> → **这正是蜂群踩坑库里那些"越改越脏"的同一病根。**

# 演示结论

## 协议可运行性：✅ 已验证

| Stage | 能否跑通 | 卡在哪 |
|---|---|---|
| 0 Onboarding | ✅ | **Gate 1 待批** |
| 1 Reference Deconstruction | ✅ 框架 | **缺主视觉参考图** |
| 2 First Brand Kit | ✅ 字体系统合规产出 | 色值/图形需先定 Logo |
| 3 Creative-Direction Review | ✅ 审计框架 + 判定逻辑完整 | 需真实产出物才能实审 |

## 三条对主人业务最直接的启发

1. **「REJECT vs REFINE」判据可直接用** —— 主人常遇"客户说不清哪里不对"，这套**量化判据**（触及 ≥2 项基础系统即重启）比凭感觉判断可靠得多。
2. **「Brand Lock 三权分立」填了蜂群的空白** —— 做参考驱动的 KV 时，明确"参考只管构图、品牌只管身份"，能避免产出变成"给别家改牌子"。
3. **「字体必须点名到字族」与主人的字体可商用铁律完全一致** —— 且它进一步要求**把字体名印在画面上**，这是防"图文不符"的一道硬保险。
