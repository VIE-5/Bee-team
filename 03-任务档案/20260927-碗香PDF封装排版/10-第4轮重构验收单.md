## 五、⚠️ 本轮发现并修复的 P0 缺陷：图版静默裁切

### 5.1 发现路径

通读联系表 + 抽页 1:1 目视时发现 **P17 板图左边缘文字被切（「版标志」应为「横用横版标志」）**、
**P70 主题海报只剩中间一条**（顶部标题带与底部 logo 带全丢）。
按「先量不猜」上 **DOM 几何探针**，实测每张 `img` 的渲染尺寸 vs 容器尺寸，拿到硬证据。

### 5.2 影响面：22 张图

| 页 | 素材原尺寸 | 容器 | 裁切 |
|---|---|---|---|
| P17 / P20 / P21 / P22 / P23（板图） | 1672×941 | 1152×478 | 左右各 ≈260px |
| P32 门帘 | 1086×1003 | 1086×543 | 上下各 ≈230px |
| P37 / P38 服务员·厨师服装 | 1024×1536 | 1024×543 | 上下各 ≈495px |
| P39 营业时间牌 / P64 品牌故事 | 1024×1064 | 1024×543 | 上下各 ≈261px |
| P66 IP文化展示 / P67 F05 主题视觉 | 1086×1003 / 1049×1039 | 1024×543 | 上下各 ≈230 / 248px |
| **P68–P71 主题海报 ×4** | 1024×1536 | 1024×543 | **上下各 ≈495px（头尾全丢）** |
| P28 名片 / P54 饮料杯 | 1619×971 / 1448×752 | 高 689.7 / 597.2 → 543 | 上下各 ≈73 / 27px |

### 5.3 根因（技术）

第 4 轮把 r3 **已验证正确的 px 硬编码上限**换成了百分比 `max-height:100%`。
而 `.frame` 的高度来自 flex 拉伸（**computed `height` 仍是 `auto`**），
百分比 `max-height` 的基准是包含块的 `height` **属性**而非 used value
→ Chrome 解析为 `none` → 图片退回原尺寸 → 被 `.frame{overflow:hidden}` 裁掉。
（`max-width:100%` 因不依赖内容高度而仍生效，**只有竖版图出事**，掩盖了问题。）

### 5.4 性质：**既有铁律的第二次复发**

该铁律 **2026-09-18 已立**并写进 VI 母版规范 §9 ——
「固定画布下百分比限高不可靠，尺寸一律硬编码 px」。
本轮属于**未立项地"顺便升级"了一段已验证正确的实现**。详见 `04-知识沉淀/踩坑库.md` 2026-09-27 专条。

### 5.5 修复

1. 回到 px 上限；`.frame` 改 `width/height:fit-content` 让图版**贴合图片**（消除"满宽白条 + 小图"）
2. 板图页去掉内联 `height:478px`（原来白浪费 120px 内容区）→ 板图由 845px 宽增至 **1055px 宽（+25%）**
3. 海报页另立页型 `.slide.poster`：**左图右栏**，海报满高 **467×700**，右栏承载 承载文案 / 文案角色
4. 副作用修正：海报右栏标题继承物料页 `padding-left:30px` 导致与下方文字不对齐 → 归零

### 5.6 机检出口（关键）

新增 `04-知识沉淀/工具/deck-benchmark/probe_fit.py`，**已双向验证**：
正式产物 PASS ／ 旧规则合成的负样本 **FAIL(9)**（页码与数值与实测逐条对应）。
→ 今后**图版类交付收尾固定 4 项**：张数 / 体积分布 / 退出码·PDF 页数 / **贴合体检**。
