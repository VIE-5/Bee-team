## 二、第 5 条：MediaBox 比例的根因实验（最小复现）

**结论：是 Chrome 打印引擎对页面框的量化，与本册 CSS／内容／单位无关。**

实验：另建**只含一个 1360×850 单色 div + `@page`** 的最小页面（无册子 CSS、无图片、无布局），
用同一 Chrome 打印管线导出后读 `/MediaBox`：

| 探针 | `@page` 声明 | 实测 MediaBox 高 | 理论值（px×0.75） | 偏差 |
|---|---|---|---|---|
| 最小页·px 单位 | `1360px 850px` | **637.91998 pt** | 637.50 | +0.41998 |
| 最小页·pt 单位 | `1020pt 637.5pt` | **637.91998 pt** | 637.50 | +0.41998 |
| 最小页·高 500px | `1360px 500px` | 375.12 pt | 375.00 | +0.12 |
| 最小页·高 1000px | `1360px 1000px` | **750.00 pt** | 750.00 | **0.00** |

- 单位改用 pt **结果完全不变** → 排除「声明单位」嫌疑；
- 高度 1000px 时**精确命中** → 偏差不是缩放系数，而是**离散步进量化**（页面框被吸附到粗网格）；
- 该偏差**与本册无关**（最小页同样复现），且**逐页一致**（55 页全为 637.92）。

**影响量化**：+0.41998 pt = **0.148 mm**，占页高 **0.066%**，全册一致、无页间不一致。
**处置**：不判缺陷；已在渲染出口新增 `--ratio` 参数，使 `1.598947` 对 1.6 目标落在容差内，
消除此类册子的**误报**（原脚本硬编码 16:9，会把 16:10 册子一律报 `[!] 非16:9`）。

## 三、第 8 条：Type3 字体 → 移交印前（登记）

Chrome `--print-to-pdf` 管线的固有产物，**册内任何改动都无法消除**（除非放弃 Chrome 打印、
改走 PDF 库自行嵌入 CIDFontType2 子集——属另立产线，不在本单范围）。留档供印前使用：

1. 字体来源 = Noto Serif SC / Noto Sans SC（思源体系等价物，**OFL，可商用**）；
2. 风险：Type3 无常规字体程序，**印厂 RIP 兼容性须实测**；
3. 字距被展开进文本流 → 复制/检索得到 `W A N X I A N G · Z U N Y I`（非缺陷）；
4. 本机 `C:/Windows/Fonts` **未装 Noto SC** → **客户机重渲 HTML 会字体漂移**，交付须带「请勿本机重渲」提示。
